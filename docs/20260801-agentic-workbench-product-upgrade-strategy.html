Product direction review · 2026.08.01

Agentic Workbench
제품 업그레이드 전략

현재 제품 상태를 목표 가치와 비교하고, “워크플로를 실행해 제품을 만드는 도구”로 발전하기 위한 과정을 정리한다.

제품 가치 중심 저장소 근거 기반 Human-in-the-loop Workflow as Product
01 · Core thesis

목표 자체는 논리적으로 정합적이다

개발 흐름은 사용자가 설계하고, 실행은 에이전트가 담당하며, 중요한 결정은 사용자가 내린다.

이 정의는 자동화의 효율과 인간의 통제를 충돌시키지 않는다. 반복 가능한 작업은 자동화하고, 제품 방향과 위험을 바꾸는 순간은 명시적인 검토 지점으로 남긴다.

워크플로 자체가 목적이 아니다. 에이전트가 올바른 데이터와 문서를 읽고 작업하며, 결과를 다음 단계의 Artifact로 전달해 최종 제품을 만드는 것이 목적이다.

03 · Product value

제품이 제공해야 할 세 가지 가치

실행 가능한 개발 과정

요구사항, Spec, Task, 구현, 검증을 대화의 연속이 아니라 재사용 가능한 워크플로로 만든다.

통제 가능한 자동화

에이전트가 백그라운드에서 진행하되 산출물 리뷰와 중요한 의사결정에서 사용자가 방향을 통제한다.

누적되는 제품 자산

실행 결과가 일회성 채팅으로 사라지지 않고 코드, 문서, 결정과 실행 이력으로 축적된다.

04 · Correct positioning

ACP도, 채팅 UI도, 데스크톱 앱도 제품의 본질은 아니다

수단

  • ACP: 에이전트 연결과 실행
  • Desktop·Web·CLI: 사용자 접점
  • MCP: 에이전트가 시스템을 제어하는 인터페이스
  • Markdown: 산출물 검토 표면

제품

사람과 에이전트가 같은 제품 개발 워크플로를 설계하고 운영하며, 그 실행을 통해 실제 소프트웨어가 만들어지는 시스템.

따라서 기술이나 특정 UI를 제품 정체성으로 설명하면 가치가 좁아진다. 중심 명사는 Agentic Workflow다.

05 · Current reality

현재 Workbench는 어디까지 왔는가

에이전트 실행

ACP 실행, 세션 복원, 스트리밍 이벤트, 권한, steer·cancel과 다중 공급자 기반.

병렬 협업

Main·Child 위임, Task 상태, 결과 보고, 입력 요청, 취소·재시도·재배정.

산출물 리뷰

Spec·Task Markdown 탐색, 렌더링, 주석과 에이전트 프롬프트 연결.

복구의 씨앗

오케스트레이션 스냅샷, revision·idempotency와 런타임 이벤트 replay 개념.

06 · Honest diagnosis

현재 제품의 정확한 위치

재사용 가능한 제품 개발 워크플로 플랫폼이라기보다, Worktree 단위 다중 에이전트 협업 워크스페이스에 가깝다.

실행 수명

Run이 세션 창에 귀속되고 창이 닫히면 취소된다. 백그라운드 지속 실행 가치와 충돌한다.

워크플로 정의

재사용·버전 관리할 Workflow Definition과 Run의 구분이 없다. 현재 모델은 Main과 direct Child 중심이다.

접속과 제어

Tauri 창 이벤트가 중심이며 여러 UI가 동일한 실행을 관찰·제어하는 제품 인터페이스가 없다.

근거: apps/agentic-workbench/src-tauri/src/lib.rs의 WindowEvent::Destroyed 처리 · inbound/tauri_commands.rs · tauri_run_event_sink.rs

08 · Confirmed initial scope

초기 제품의 공식 범위

사용자

로컬 저장소에서 여러 AI Agent를 운영하는 1인 개발자·기술 창업자.

제품 단위

Product 하나와 Repository 하나. Worktree는 병렬 Task를 격리하는 실행 자원.

대표 결과

테스트를 통과하고 사용자 검토를 마친 Ready to Merge 기능 변경.

Workflow

제품이 제공하는 검증된 기본 흐름. 초기에는 구조보다 자동화 정책을 설정.

실행 환경

로컬 Background Service가 Run을 소유하고 Desktop UI가 관찰·제어.

초기 제외

자유형 그래프 편집, 다중 저장소, 원격 실행, 팀 협업과 자동 병합.

사용자 병합

기본 필수 개입은 세 Gate로 제한한다. 최종 승인은 병합을 자동 실행하지 않으며 사용자의 명시적 병합 명령을 기다린다.

10 · Execution contract

Agent 자동화의 경계

자율 실행

Sub-agent 생성, worktree 할당, Task 세분화, 최대 2회 재시도, 재배정, Artifact 종합.

사용자 승인

Spec·완료 조건, 핵심 설계, 범위 확대, 의미적 충돌과 최종 병합.

완료 근거

모든 Sub-agent는 변경 파일, 테스트, 완료 조건, 위험을 담은 Task Result Artifact를 제출.

Agent 프로세스 종료는 Task 완료가 아니다. Artifact와 검증 근거가 있어야 완료다.
11 · Strategic choice

새로 만드는 것이 아니라 현재 강점을 승격한다

ACP Agent Runtime
→
Main·Child Orchestration
→
Workflow 실행 역량
→
제품 개발 자동화

유지할 것

ACP 실행 코어, Task·Report 모델, 사용자 권한 개입, Markdown·Spec 리뷰, 재시도와 결과 수집.

재정의할 것

현재 Main·Child 오케스트레이션을 제품 전체가 아니라 범용 워크플로 안의 강력한 실행 Node 또는 Sub-workflow로 본다.

12 · Required product surfaces

Agent와 Data를 다루는 네 가지 도구

Agent UI

에이전트의 역할, 작업, 진행 상태, 요청과 결과를 이해하고 필요한 순간에 개입한다.

Workflow Design

에이전트, 데이터, 단계, 분기, 검토 지점과 완료 조건을 구성한다.

Workflow Inspection

설계된 흐름의 누락, 모순, 위험, 도달 불가능한 단계와 필요한 입력을 점검한다.

Run Inspection

실행 중인 흐름, 대기 중인 결정, 생성된 Artifact와 실패·재시도 상태를 확인한다.

이 네 표면은 별도 제품이 아니라 하나의 Workflow Model과 Run 상태를 서로 다른 관점으로 보여주는 도구다.

Artifact가 필요한 이유

에이전트 응답을 일회성 메시지가 아니라 출처, 상태, 버전, 검토 결과를 가진 워크플로 데이터로 만든다.

문서 시스템이 필요한 이유

에이전트가 읽어야 할 요구사항, 결정, 규칙과 기존 산출물을 목적과 단계에 맞게 찾고 전달해야 결과의 일관성이 유지된다.

14 · Upgrade journey

목표 제품으로 가는 다섯 단계

실행 독립성

UI가 닫혀도 실행이 지속되고 다시 접속해 현재 상태를 확인할 수 있게 한다.

워크플로 자산화

검증된 기본 흐름을 Definition과 Run으로 분리하고 저장·버전·재사용한다.

인간 개입의 구조화

문서·Artifact와 중요한 결정을 워크플로의 명시적인 단계와 기록으로 승격한다.

공동 편집

사람은 Visual·DSL로, 에이전트는 MCP로 같은 워크플로를 만들고 개선한다.

접점 확장

Desktop, Web, CLI와 원격 채널이 동일한 실행 상태와 의사결정 흐름에 연결된다.

15 · Validation gates

각 단계는 기능 목록이 아니라 제품 가치로 검증한다

지속성

사용자가 UI를 닫아도 작업은 계속되고, 돌아왔을 때 맥락 손실 없이 이어갈 수 있는가?

재사용성

성공한 개발 과정을 다른 프로젝트에서 다시 실행하고 개선할 수 있는가?

통제 가능성

사용자가 중요한 순간을 놓치지 않고 결과와 선택의 이유를 확인할 수 있는가?

일관성

어떤 UI나 에이전트로 접속해도 같은 실행 상태와 결정을 보는가?

추적성

어떤 워크플로와 결정이 현재 코드와 제품 결과를 만들었는지 설명할 수 있는가?

완결성

하나의 대표 워크플로가 아이디어에서 검증된 소프트웨어 제품까지 끝까지 이어지는가?

16 · Priority

가장 먼저 증명해야 할 것

“워크플로 편집기가 멋진가?”보다 먼저, “사용자가 자리를 비운 동안에도 개발 흐름이 안전하게 계속되고, 필요한 순간에만 정확히 돌아오게 하는가?”를 증명한다.

이 경험이 성립해야 Visual Builder, DSL, MCP 편집과 원격 접속이 하나의 제품 가치를 확장한다. 반대로 지속 실행과 산출물·결정의 연결이 약하면 여러 인터페이스는 복잡성만 늘린다.

17 · Product narrative

최종 제품 메시지

Agentic Workbench는 1인 개발자가 기능 개발 Workflow를 실행해 Ready to Merge 소프트웨어 변경을 만드는 로컬 우선 Human-in-the-loop 플랫폼이다.

사람

목표를 정하고 흐름을 설계하며 중요한 산출물과 결정을 책임진다.

에이전트

워크플로 안에서 분석, 구현, 테스트와 반복 작업을 수행한다.

Workbench

에이전트, 문서, Artifact, 결정과 실행 상태를 연결해 제품이 만들어지는 흐름을 지속한다.
