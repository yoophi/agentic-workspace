# 창 닫힘은 데스크톱이 작업대를 명시적으로 닫는 것이며, 연결 끊김은 run 취소가 아니다

오늘 세션 창이 닫히면 그 창의 run이 취소되고 교환 작업 영역이 지워진다. 040에서 사용자에게 보이는 이 동작은 유지하되, 의미를 "데스크톱이 `bench.close`를 호출했다"로 바꾼다. 데스크톱은 창이 `Destroyed`될 때 그 창의 작업대를 닫고, 작업대는 처음 쓸 때 연다(창 생성 코드는 바뀌지 않는다). 이벤트 구독이 끊기는 것만으로는 작업대도 run도 끝나지 않는다(정본 결정 8). `bench.close`는 멱등이다.

## Considered Options

- 작업대를 구독 연결의 수명에 묶기 — 정리는 자동이지만 잠깐의 연결 끊김이 run 취소가 된다.
- lease(갱신 없으면 자동 종료) — 닫지 않고 사라진 HTTP 호출자까지 막지만, 지금 호출자는 데스크톱과 테스트뿐이라 이르다(3단계).

## Consequences

- "창을 닫아도 run이 계속되는" 동작은 데스크톱이 `bench.close`를 부르지 않는 것만으로 가능해진다. 그 결정은 daemon(5단계 이후)과 함께 한다.
- 닫지 않고 사라진 비데스크톱 호출자의 작업대는 3단계의 lease로 정리한다.
