# Feature Specification: Agent Run 탭·타일 워크스페이스

**Feature Branch**: `032-agent-run-tiles`

**Created**: 2026-07-27

**Status**: Implemented

**Input**: User description: "현재 에이전트 런 구간의 탭 보기를 유지하면서 타일 보기를 추가하고, 탭과 타일을 전환하며 현재 창 옆에 새 타일 열기 등의 명령을 실행할 수 있도록 한다. 에이전트 런 영역끼리 상호 통신할 수 있는 인터페이스를 추가한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 탭과 타일 보기 전환 (Priority: P1)

사용자는 하나의 에이전트 런에 집중할 때 기존 탭 보기를 사용하고, 여러 에이전트의 진행 상황을 동시에 비교하거나 협업시킬 때 타일 보기로 전환할 수 있다. 보기 전환은 실행 중인 에이전트를 중단하거나 패널 상태를 초기화하지 않는다.

**Why this priority**: 기존 사용 흐름을 보존하면서 여러 런을 동시에 관찰할 수 있게 하는 것이 기능의 기본 가치이자 다른 타일 명령과 통신 기능의 전제다.

**Independent Test**: 세 개의 에이전트 런 패널을 만들고 각 패널에 서로 다른 대화와 실행 상태를 둔 뒤 탭 보기와 타일 보기를 반복 전환하여 패널 수, 활성 런, 입력 초안, 스크롤 위치 및 실행 상태가 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 여러 에이전트 런 패널이 탭으로 열려 있음, **When** 사용자가 타일 보기를 선택함, **Then** 열려 있는 패널이 동시에 식별 가능한 타일로 표시되고 실행 상태가 유지된다.
2. **Given** 여러 타일이 표시되어 있음, **When** 사용자가 탭 보기를 선택함, **Then** 마지막으로 초점을 둔 타일이 활성 탭으로 표시되고 다른 런은 닫히거나 중단되지 않는다.
3. **Given** 에이전트가 출력을 스트리밍 중임, **When** 사용자가 보기 모드를 전환함, **Then** 출력 스트림과 권한 요청 및 현재 프롬프트 상태가 해당 런에 계속 연결된다.
4. **Given** 키보드만 사용하는 사용자, **When** 보기 전환 컨트롤과 각 패널로 이동함, **Then** 현재 보기 모드와 초점 대상이 보조 기술에 전달되고 모든 열린 패널에 도달할 수 있다.

---

### User Story 2 - 현재 타일 옆에 새 에이전트 런 열기 (Priority: P1)

사용자는 현재 초점을 둔 타일의 명령 메뉴에서 새 에이전트 런을 오른쪽 또는 아래에 열어 원하는 협업 구도를 즉시 구성할 수 있다.

**Why this priority**: 단순 자동 격자보다 사용자가 공간적 관계를 명시할 수 있어야 “현재 창 옆에 새 타일 열기”가 예측 가능하고 반복 가능한 작업 흐름이 된다.

**Independent Test**: 단일 타일에서 오른쪽 열기, 아래 열기를 순서대로 실행하고 새 타일의 위치, 초점 이동, 기존 타일 크기 조정 및 고유 패널 상태를 검증한다.

**Acceptance Scenarios**:

1. **Given** 하나의 현재 타일이 있음, **When** 사용자가 "오른쪽에 새 타일 열기"를 실행함, **Then** 현재 타일과 같은 높이를 공유하는 새 에이전트 런 타일이 오른쪽에 생성되고 새 타일이 초점을 받는다.
2. **Given** 현재 타일이 있음, **When** 사용자가 "아래에 새 타일 열기"를 실행함, **Then** 현재 타일과 같은 너비를 공유하는 새 타일이 아래에 생성되고 새 타일이 초점을 받는다.
3. **Given** 탭 보기에서 현재 패널이 선택되어 있음, **When** 사용자가 인접 타일 열기 명령을 실행함, **Then** 새 패널이 생성되고 타일 보기로 전환되어 현재 패널과 새 패널이 요청한 방향으로 함께 표시된다.
4. **Given** 타일이 최소 사용 가능 크기에 도달함, **When** 사용자가 더 이상 해당 방향으로 분할할 수 없는 명령을 선택함, **Then** 시스템은 기존 배치를 훼손하지 않고 명령을 수행할 수 없는 이유를 알린다.

### User Story 3 - 타일 배치 조작 및 닫기 (Priority: P2)

사용자는 타일 사이 경계를 조절하고, 원하는 타일을 활성화하며, 불필요한 추가 런을 닫을 수 있다. 실행 중인 타일을 닫을 때는 기존과 같은 명시적 취소 확인을 거친다.

**Why this priority**: 여러 런을 장시간 함께 사용하는 화면에서는 각 런의 중요도와 콘텐츠 길이에 맞춰 공간을 관리해야 한다.

**Independent Test**: 중첩 분할 배치에서 경계 크기 조정, 타일 초점 변경, 유휴 타일 닫기, 실행 중 타일 닫기 취소 및 확인을 각각 수행해 남은 레이아웃과 런 상태를 확인한다.

**Acceptance Scenarios**:

1. **Given** 둘 이상의 타일이 있음, **When** 사용자가 타일 경계를 조절함, **Then** 인접 타일만 유효한 최소 크기 범위 안에서 크기가 바뀐다.
2. **Given** 추가 타일이 유휴 상태임, **When** 사용자가 타일을 닫음, **Then** 해당 타일이 제거되고 인접 공간이 남은 타일에 재할당된다.
3. **Given** 추가 타일에서 에이전트가 실행 중임, **When** 사용자가 타일을 닫으려 함, **Then** 실행 취소 영향을 설명하는 확인 절차가 표시되고 취소를 선택하면 타일과 런이 유지된다.
4. **Given** 현재 타일이 닫힘, **When** 닫기 작업이 완료됨, **Then** 공간적으로 가장 가까운 남은 타일이 초점을 받고 유효한 활성 패널이 된다.

### User Story 4 - 에이전트 런 간 메시지 전달 (Priority: P2)

사용자 또는 실행 중인 에이전트는 같은 worktree 세션 창에 열린 다른 에이전트 런을 대상으로 메시지를 전달할 수 있다. 수신 런의 상태에 따라 즉시 전달, 대기열 추가 또는 입력 초안으로 준비하며, 발신자·수신자·전달 상태를 양쪽에서 추적할 수 있다.

**Why this priority**: 여러 런을 나란히 표시하는 것을 실제 협업으로 확장하려면 런 간 명시적이고 범위가 제한된 통신 계약이 필요하다.

**Independent Test**: 동일 창의 두 런과 다른 창의 한 런을 준비하고, 동일 창 런 사이의 즉시 전달·대기·초안 전달이 기록되는지 및 다른 창 런으로의 전달이 차단되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 동일 worktree 세션 창에 발신 및 수신 런이 있음, **When** 사용자가 발신 타일에서 수신 타일과 전달 방식을 선택해 메시지를 보냄, **Then** 수신 타일은 해당 방식으로 메시지를 받고 양쪽 타일에 발신자, 수신자 및 전달 상태가 표시된다.
2. **Given** 수신 런이 현재 응답을 생성 중임, **When** 즉시 전송이 안전하지 않은 전달 요청이 도착함, **Then** 요청은 사용자가 선택한 대기 또는 초안 상태로 보존되며 기존 응답을 암묵적으로 취소하지 않는다.
3. **Given** 실행 중인 에이전트가 피어 런 목록을 요청함, **When** 시스템이 통신 가능한 대상을 반환함, **Then** 같은 창과 worktree에 속하고 닫히는 중이 아닌 런만 식별 가능한 이름과 상태로 제공된다.
4. **Given** 에이전트가 허용된 피어 런에 메시지를 전달함, **When** 수신 런이 메시지를 수락하거나 거부함, **Then** 결과가 발신 런에 반환되고 교환 기록에 반영된다.
5. **Given** 발신 런이 다른 창, 다른 worktree 또는 이미 닫힌 런을 대상으로 지정함, **When** 전달을 시도함, **Then** 메시지는 전달되지 않고 범위 또는 대상 오류가 명확히 반환된다.

### Edge Cases

- 열린 패널이 하나뿐인 경우 타일 보기는 단일 타일을 전체 영역에 표시하고 탭 보기와 동일한 런 상태를 공유한다.
- 보기 전환 중 권한 요청 다이얼로그가 열려 있으면 요청의 소유 런과 응답 대상이 바뀌지 않는다.
- 스트리밍 중인 여러 타일 중 하나에 초점을 옮겨도 다른 타일의 자동 스크롤 또는 사용자 스크롤 위치가 초기화되지 않는다.
- 깊게 중첩된 분할이 가용 영역을 초과하면 추가 분할은 거부되며 기존 레이아웃은 유지된다.
- 창 크기가 줄어 최소 타일 크기를 모두 만족할 수 없으면 레이아웃은 안전하게 압축 가능한 범위까지만 조정하고, 필요하면 탭 보기 전환 안내를 제공한다.
- 실행 중인 타일을 닫거나 모든 추가 타일을 닫아도 필수 Main 런 패널은 제거되지 않는다.
- 통신 메시지가 공백이거나 허용 크기를 초과하거나 수신 타일이 닫히는 중이면 전달하지 않고 원인을 반환한다.
- 동일 메시지가 재시도되거나 이벤트가 중복 수신되어도 수신 런에는 한 번만 적용되고 교환 상태는 역행하지 않는다.
- 수신 런이 전달 직전에 종료되거나 새 런 ID로 전환되면 오래된 대상 런으로 메시지를 보내지 않고 재선택을 요구한다.
- 탭 보기에서 백그라운드 패널이 통신 메시지를 받으면 패널 상태는 갱신되지만 사용자의 활성 탭을 임의로 전환하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 기존 탭 보기와 모든 열린 에이전트 런 패널의 상태 및 동작을 유지해야 한다.
- **FR-002**: 사용자는 에이전트 런 영역을 탭 보기와 타일 보기 사이에서 전환할 수 있어야 한다.
- **FR-003**: 보기 전환은 패널 생성·삭제, 실행 중단, 세션 재시작, 입력 초안 삭제 또는 런별 탐색 상태 초기화를 유발하지 않아야 한다.
- **FR-004**: 시스템은 보기 모드와 별개로 현재 초점을 받은 패널을 하나 식별하고 명령 및 외부 프롬프트의 기본 대상을 해당 패널로 정해야 한다.
- **FR-005**: 타일 보기에서는 모든 열린 패널을 각기 독립적인 타일로 동시에 표시해야 한다.
- **FR-006**: 사용자는 현재 타일의 오른쪽 또는 아래에 새 에이전트 런 타일을 열 수 있어야 한다.
- **FR-007**: 탭 보기에서 인접 타일 열기 명령을 실행하면 현재 패널과 새 패널의 관계가 보이도록 타일 보기로 전환해야 한다.
- **FR-008**: 새 타일은 고유한 패널 ID와 독립된 런, 대화, 입력, 스크롤, 미니맵 및 닫기 상태를 가져야 한다.
- **FR-009**: 시스템은 중첩된 가로·세로 분할 관계와 각 분할 비율을 유지해야 한다.
- **FR-010**: 사용자는 인접 타일 사이 경계를 조절할 수 있어야 하며 각 타일은 핵심 런 상태와 프롬프트 조작을 사용할 수 있는 최소 크기를 보장해야 한다.
- **FR-011**: 추가 타일을 닫으면 해당 타일을 포함하던 분할 관계를 제거하고 남은 형제 타일 또는 분할에 공간을 재할당해야 한다.
- **FR-012**: Main 패널은 닫을 수 없어야 하며 실행 중인 추가 패널의 닫기에는 실행 취소 확인이 필요하다.
- **FR-013**: 각 타일은 제목, 실행 상태, 활성 여부 및 닫기 가능 여부를 식별할 수 있는 헤더와 명령 진입점을 제공해야 한다.
- **FR-014**: 보기 전환, 타일 초점 이동, 인접 타일 열기, 타일 닫기 및 경계 조절은 키보드로 수행할 수 있고 보조 기술에 이름·상태·관계를 제공해야 한다.
- **FR-015**: 시스템은 동일 worktree 세션 창 내의 열려 있고 닫히는 중이 아닌 패널을 통신 가능한 피어로 조회할 수 있어야 한다.
- **FR-016**: 통신 대상 식별에는 변경 가능한 화면 순서나 제목이 아니라 안정적인 패널 ID와 현재 런 ID를 함께 사용해야 한다.
- **FR-017**: 사용자 또는 에이전트는 발신 패널, 수신 패널, 메시지, 전달 방식 및 고유 요청 ID를 포함한 메시지 전달을 요청할 수 있어야 한다.
- **FR-018**: 지원 전달 방식은 수신 런에 즉시 전송, 현재 작업 이후 대기, 입력 초안 준비를 포함해야 하며 기존 실행을 암묵적으로 취소하지 않아야 한다.
- **FR-019**: 시스템은 발신 및 수신 패널이 같은 창과 worktree에 속하는지, 요청 주체가 발신 런을 소유하는지, 수신 패널과 런이 현재 유효한지 검증해야 한다.
- **FR-020**: 통신 요청은 대기, 전달, 수락, 거부, 실패 또는 취소 상태와 실패 사유를 추적하고 발신·수신 양쪽에서 확인 가능해야 한다.
- **FR-021**: 동일 요청 ID의 통신 요청은 최대 한 번만 수신 런에 적용되어야 한다.
- **FR-022**: 탭 보기의 비활성 패널 또는 화면 밖 타일도 통신 상태와 런 이벤트를 계속 수신해야 하며 사용자 초점을 임의로 빼앗지 않아야 한다.
- **FR-023**: 기존 workspace에서 보내는 주석 및 SDD 프롬프트는 현재 초점 패널로 라우팅하는 동작을 유지해야 한다.
- **FR-024**: 타일 추가 및 통신 실패는 기존 패널 배치와 활성 런을 훼손하지 않고 사용자가 복구할 수 있는 안내를 제공해야 한다.
- **FR-025**: 시스템은 통신 메시지의 빈 값, 최대 허용 크기, 닫힘 상태 및 오래된 런 대상을 검증해야 한다.

### Key Entities

- **Agent Run Panel Slot**: 하나의 에이전트 런 화면을 나타내는 안정적인 패널 단위. 패널 ID, 종류, 제목, 현재 런 ID, 실행·닫기 상태와 패널별 UI 상태를 가진다.
- **Agent Run Workspace**: 한 worktree 세션 창에 열린 패널 집합, 현재 보기 모드, 현재 초점 패널 및 타일 레이아웃을 함께 관리하는 화면 상태.
- **Tile Layout Node**: 하나의 패널을 가리키는 리프 또는 가로·세로 방향, 분할 비율 및 자식 노드를 가진 분할 관계.
- **Peer Agent Endpoint**: 같은 창과 worktree 범위에서 메시지를 받을 수 있는 패널과 현재 런의 안정적인 주소 및 표시용 상태.
- **Agent Exchange**: 발신 패널·런, 수신 패널·런, 메시지, 전달 방식, 고유 요청 ID, 생성 시각 및 전달 상태를 가진 런 간 통신 기록.
- **Workspace Command**: 현재 초점 패널을 기준으로 보기 전환, 인접 타일 열기, 타일 닫기 또는 피어 메시지 전달을 요청하는 사용자 명령.

## Constitution Alignment *(mandatory)*

- **Monorepo boundary**: 사용자 화면과 workspace 조합은 `apps/agentic-workbench`에 둔다. 런 간 통신의 순수 계약이 두 번째 앱에서 실제 소비되기 전에는 `packages/*` 또는 `crates/*`로 승격하지 않는다. ACP 세션 실행 자체의 공용 계약은 기존 `crates/acp-agent-core`를 변경하지 않고 AW 전용 오케스트레이션으로 제한한다.
- **Frontend layering**: 세션 페이지는 `pages/project-worktree-session`에서 worktree workspace와 agent workspace를 조합한다. 탭·타일 전환, 분할 명령, 피어 선택 및 교환 표시 같은 사용자 상호작용은 `features/agent-run`, 패널·레이아웃·교환의 순수 상태와 API 어댑터는 `entities/agent-run`, 범용 버튼·메뉴·분할 프리미티브는 기존 `components/ui` 또는 `shared`에 둔다. 앱 전체 라우팅이나 provider 변경이 필요할 때만 `app`을 수정한다.
- **Backend boundary**: 런 소유권과 교환 검증 모델은 `domain`, 피어 조회·전달·상태 전이 유스케이스는 `application`, Tauri 및 MCP 명령은 `inbound`, 현재 세션 레지스트리와 이벤트 전달 구현은 `infrastructure`에 둔다. Tauri/MCP 경계는 검증 후 application service에 위임하며 영속 또는 라우팅 로직을 직접 포함하지 않는다.
- **Shared core vs UI**: 레이아웃 reducer, 인접 분할·제거 알고리즘, 교환 상태 전이는 UI와 분리한 순수 로직으로 먼저 구현한다. 타일 UI는 AW 작업 화면 요구에 특화되므로 다른 앱의 두 번째 소비가 생기기 전에는 공유 UI로 추출하지 않는다.
- **Persistence and safety**: v1 레이아웃과 교환 기록은 세션 창 수명 동안 유지하며 앱 재시작 후 복원은 요구하지 않는다. 모든 피어 조회와 메시지 전달은 창 label, canonical worktree 경로, 발신 panel/run 소유권 및 수신 panel/run 유효성을 검증한다. 메시지 크기 제한과 요청 ID 중복 제거를 적용한다.
- **Documentation and Storybook**: `docs/agent-run-tile-workspace.md`에 한국어 구조 문서와 Mermaid 흐름을 추가한다. 재사용 가능한 보기 전환기, 타일 헤더, 분할 workspace, 피어 선택 및 교환 상태 UI는 atomic design 분류에 맞춰 빈 상태, 단일/다중 타일, 실행 중, 오류, 좁은 폭 상태의 Storybook 스토리를 등록한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 세 개의 실행 중 또는 유휴 패널로 탭·타일 보기를 20회 왕복 전환하는 검증에서 패널·런·초안·스크롤 상태 손실과 실행 중단이 0회다.
- **SC-002**: 단일 타일에서 오른쪽 및 아래 열기 명령을 각각 실행하는 모든 검증에서 새 타일이 한 번의 명령으로 요청한 인접 위치에 생성되고 즉시 키보드 초점을 받는다.
- **SC-003**: 최대 8개의 열린 패널과 4단계 중첩 분할을 포함한 검증에서 모든 타일이 고유한 런 상태를 표시하고 경계 조절·초점 이동·닫기 후 유효한 레이아웃을 유지한다.
- **SC-004**: 보기 모드 전환과 인접 타일 생성은 1440×900 데스크톱 환경에서 사용자 입력 후 200ms 이내에 조작 가능한 화면 상태로 반영된다.
- **SC-005**: 동일 창·worktree의 피어 간 즉시·대기·초안 전달 검증은 100% 올바른 수신 패널에 한 번만 적용되고, 다른 창·worktree·닫힌 런 대상 전달 검증은 100% 차단된다.
- **SC-006**: 모든 교환 검증에서 발신자는 요청 후 1초 이내에 대기·전달·거부·실패 중 현재 상태를 확인할 수 있으며 최종 상태와 실패 사유가 양쪽 런에서 일치한다.
- **SC-007**: 키보드 전용 검증에서 사용자는 보기 모드 전환, 모든 타일 순회, 인접 타일 열기, 경계 조절, 추가 타일 닫기 및 피어 메시지 전달을 포인터 없이 완료할 수 있다.
- **SC-008**: 기존 탭 선택, extra 패널 생성·닫기, workspace 프롬프트 라우팅, 출력 스트리밍, 권한 응답 및 미니맵 동작의 회귀 테스트가 모두 통과한다.

## Assumptions

- v1은 하나의 AW worktree 세션 창 안에서만 타일과 통신을 지원하며 창 간 또는 worktree 간 에이전트 통신은 범위 밖이다.
- 타일 배치는 자유형 드래그 캔버스가 아니라 결정적인 가로·세로 중첩 분할 구조다.
- 인접 타일 열기의 기본 방향은 오른쪽이며 명령 메뉴에서 아래 방향을 선택할 수 있다. 왼쪽·위쪽 열기는 v1 범위 밖이지만 구조적으로 확장 가능하게 설계한다.
- 탭 보기에서 타일 보기로 진입할 때마다 기존 탭 순서를 유지하는 균등한 가로 배치로 정규화한다. 세 패널은 `1:1:1` 비율이 되며, 사용자가 만든 분할 비율은 같은 타일 보기 세션 안에서만 유지한다.
- 동시에 열린 패널 수는 기존 backend 동시 실행 한도와 별개이며, 화면 안정성과 테스트 범위를 위해 v1 UI 권장 최대를 8개로 둔다.
- "상호 통신"은 동일 세션 창에서 사용자 또는 에이전트가 명시적으로 대상 런과 전달 방식을 선택해 텍스트 메시지를 보내는 것을 의미한다. 파일 복사, 공유 메모리, 자동 무제한 대화 및 다른 런의 권한 대행은 포함하지 않는다.
- 실행 중 수신 런에 대한 기본 전달 방식은 대기이며, 즉시 전달은 해당 런이 지원하고 사용자가 명시적으로 선택한 경우에만 사용한다.
- 교환 기록과 타일 레이아웃의 앱 재시작 후 영속화는 v1 범위 밖이며 별도 스펙으로 확장한다.
