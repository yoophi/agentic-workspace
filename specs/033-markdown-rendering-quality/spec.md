# Feature Specification: Markdown 렌더링 품질 개선

**Feature Branch**: `033-markdown-rendering-quality`

**Created**: 2026-07-28

**Status**: Draft

**Input**: User description: "현재 markdown 기반의 preview 및 annotation 기능이 구성되어 있지만, 실제 마크다운의 모든 스펙을 준수하고 있지는 않음. 목록의 이어쓰기 같은 사례를 포함한 렌더링 품질 테스트케이스를 조사·추가하고, Markdown 스펙에 맞는 HTML이 작성되도록 렌더링 품질을 높인다." / "AW 패널 안의 Markdown preview에서 annotate 영역을 보이거나 숨길 수 있어야 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 표준 Markdown 문서 정확히 미리보기 (Priority: P1)

사용자는 일반적인 Markdown 문서를 열었을 때 목록, 목록 안의 이어지는 문단, 중첩 구조, 코드 및 인라인 서식이 문서의 의미와 계층을 보존한 HTML로 표시되기를 원한다. 예를 들어 목록 항목 다음 줄에 이어 쓴 텍스트는 목록 밖의 독립 문단이 아니라 해당 항목의 내용으로 읽힌다.

**Why this priority**: 올바른 미리보기는 주석을 달기 전에 문서 의미를 신뢰할 수 있게 하는 기본 가치다.

**Independent Test**: 대표 Markdown 코퍼스의 각 입력을 미리보기로 렌더링하여 예상 HTML 구조와 표시 텍스트를 비교한다. 특히 한 줄짜리 목록, 이어쓰기 목록, 빈 줄을 포함한 목록, 중첩 목록을 각각 확인한다.

**Acceptance Scenarios**:

1. **Given** 목록 항목 바로 다음 줄에 들여쓰기 없이 이어지는 텍스트가 있는 문서, **When** 사용자가 미리보기를 열면, **Then** 목록과 목록 항목의 의미가 유지되고 이어지는 텍스트가 그 항목에 포함되어 표시된다.
2. **Given** 중첩된 순서·비순서 목록과 여러 문단을 가진 목록 항목이 있는 문서, **When** 미리보기가 표시되면, **Then** 항목 순서, 중첩 관계, 문단 구분 및 시작 번호가 원문 의미와 일치한다.
3. **Given** 제목, 인용문, 코드 블록, 링크, 강조, 취소선, 표 또는 작업 목록이 섞인 문서, **When** 사용자가 미리보기를 열면, **Then** 각 요소가 서로의 문법 해석을 깨뜨리지 않고 의미에 맞는 HTML 구조로 표시된다.

---

### User Story 2 - 주석을 보존한 정확한 문서 읽기 (Priority: P1)

사용자는 문서에 블록 또는 선택 영역 주석이 있어도 Markdown의 구조와 원문 선택 위치가 변하지 않는 상태에서 내용을 읽고 주석을 관리할 수 있다.

**Why this priority**: 렌더링 정확성을 높이는 과정에서 기존 주석의 대상과 조작성이 깨지면 Annotator의 핵심 사용 흐름이 훼손된다.

**Independent Test**: 목록 이어쓰기, 중첩 목록, 인라인 서식을 포함한 문서에 블록·인라인 주석을 각각 적용하고, 렌더링 전후의 주석 대상, 주석 표시, 편집 및 취소 동작을 검증한다.

**Acceptance Scenarios**:

1. **Given** 복합 목록 안의 텍스트 또는 목록 전체에 연결된 주석, **When** 사용자가 문서를 미리보기로 읽으면, **Then** 주석은 의도한 텍스트 또는 블록에만 표시되고 문서의 목록 구조를 변경하지 않는다.
2. **Given** 주석이 있는 문서에 표준 Markdown 코퍼스 사례가 포함됨, **When** 사용자가 주석을 편집·취소하거나 블록 주석을 추가하면, **Then** 관련 주석만 변경되고 다른 문서 영역 및 Markdown 해석은 유지된다.
3. **Given** 해석하기 어려운 Markdown 또는 지원하지 않는 확장 문법이 있는 문서, **When** 미리보기를 열면, **Then** 애플리케이션은 오류로 중단되지 않고 읽을 수 있는 안전한 결과를 제공하며 기존 주석을 잃지 않는다.

---

### User Story 3 - 렌더링 품질을 지속적으로 검증 (Priority: P2)

유지보수자는 표준에 근거한 테스트 사례 모음과 예상 결과를 통해 렌더링 변경이 Markdown 의미나 HTML 구조를 훼손하는지 빠르게 확인할 수 있다.

**Why this priority**: 개별 버그 수정만으로는 다양한 Markdown 조합에서 같은 문제가 재발하기 쉽다.

**Independent Test**: 품질 코퍼스 전체를 실행하여 각 사례의 입력, 기대 구조, 실제 구조 및 주석 호환 결과가 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 렌더링 규칙이 변경됨, **When** 유지보수자가 품질 테스트를 실행하면, **Then** 사례별로 실패한 입력과 기대한 문서 구조를 식별할 수 있다.
2. **Given** 발견된 표준 호환성 회귀가 있음, **When** 유지보수자가 최소 재현 Markdown과 기대 결과를 추가하면, **Then** 해당 사례는 이후 품질 코퍼스에 포함되어 다시 발생하면 실패한다.
3. **Given** 새 품질 코퍼스가 추가됨, **When** 기존 미리보기 및 주석 테스트를 실행하면, **Then** 기존 지원 문법과 주석 흐름에 대한 회귀가 함께 검증된다.

---

### User Story 4 - AW 미리보기 공간에 맞춰 주석 영역 전환 (Priority: P2)

AW 사용자는 패널 안에서 Markdown 문서를 읽을 때 주석 목록과 에이전트용 주석 내용을 필요할 때만 보고, 평소에는 이를 숨겨 미리보기 본문에 더 넓은 공간을 사용하기를 원한다.

**Why this priority**: 패널은 데스크톱 화면의 일부만 차지하므로, 주석을 작성하지 않는 읽기 작업에서 고정 주석 영역은 긴 줄과 복합 Markdown 구조를 읽기 어렵게 만든다.

**Independent Test**: 주석이 있는 AW Markdown 문서를 열어 주석 영역 표시 상태를 전환하고, 본문 폭·주석 수·기존 주석·에이전트 전송 내용을 비교한다.

**Acceptance Scenarios**:

1. **Given** AW의 패널 내 Markdown 미리보기에 문서가 열려 있음, **When** 사용자가 주석 영역 숨기기를 선택하면, **Then** 주석 목록과 주석 관련 보조 내용은 보이지 않고 미리보기 본문은 확보된 가로 공간을 사용한다.
2. **Given** 주석 영역이 숨겨져 있음, **When** 사용자가 주석 영역 보이기를 선택하면, **Then** 같은 문서의 주석 수, 선택 영역 표시, 주석 목록 및 에이전트용 주석 내용을 다시 확인할 수 있다.
3. **Given** 주석을 작성하거나 편집하는 중인 문서에서 사용자가 주석 영역 표시 상태를 전환함, **When** 전환이 완료되면, **Then** 문서, 기존 주석 및 진행 중인 주석 작업이 의도치 않게 삭제되거나 다른 문서로 이동하지 않는다.

### Edge Cases

- 목록 항목 안에 빈 줄, 이어지는 문단, 인용문, 코드 블록, 중첩 목록 또는 작업 목록이 포함되어도 부모 목록과 항목의 의미를 유지한다.
- 목록처럼 보이는 기호가 코드 블록, 인라인 코드 또는 이스케이프된 텍스트에 있을 때는 목록으로 해석하지 않는다.
- 목록의 시작 번호가 1이 아니거나 항목 번호가 건너뛰어도 원문이 지정한 순서 정보를 보존한다.
- 공백만 있는 줄, 탭과 공백의 혼합 들여쓰기, 줄 끝 공백 및 서로 다른 줄바꿈 방식이 문서 전체를 깨뜨리지 않는다.
- 잘못 닫힌 강조, 링크 또는 목록 표식처럼 불완전한 입력은 읽을 수 있는 텍스트를 유지하고 미리보기를 중단시키지 않는다.
- 주석 범위가 구조화된 요소의 일부를 가리키거나 문서 갱신으로 더 이상 일치하지 않을 때, 다른 범위로 임의 이동하지 않는다.
- 원시 HTML, 스크립트성 URL 또는 기타 활성 콘텐츠는 현재 안전 정책을 약화시키거나 실행해서는 안 된다.
- 주석 영역이 숨겨진 상태에서 문서를 전환하거나 창 폭이 좁아져도, 사용자는 주석 영역을 다시 표시할 수 있고 미리보기 자체가 가로 스크롤 전용 화면으로 바뀌지 않는다.
- 주석이 없는 문서와 주석이 있는 문서 모두에서 표시 전환 제어는 명확한 현재 상태와 접근 가능한 이름을 제공한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 CommonMark 핵심 문법의 블록 및 인라인 의미를 보존하는 HTML 미리보기를 제공해야 한다.
- **FR-002**: 시스템은 현재 제품에서 제공하는 GitHub Flavored Markdown 확장(표, 작업 목록, 취소선, 자동 링크)을 기존 동작과 호환되게 표시해야 한다.
- **FR-003**: 시스템은 목록 항목에 속한 이어쓰기 텍스트, 빈 줄로 분리된 문단, 중첩 목록, 인용문 및 코드 블록을 부모 목록·항목과의 관계를 보존해 표시해야 한다.
- **FR-004**: 시스템은 순서 목록의 시작 번호와 중첩 관계, 비순서 목록의 계층, 작업 목록의 완료 상태를 원문 의미에 따라 표시해야 한다.
- **FR-005**: 시스템은 코드 블록·인라인 코드·이스케이프된 기호를 일반 Markdown 문법과 구분하여 목록 또는 다른 구조로 오해석하지 않아야 한다.
- **FR-006**: 시스템은 Markdown 문서에서 생성되는 HTML이 유효한 문서 계층을 이루도록 하며, 블록 요소를 부적절한 인라인 또는 문단 컨테이너 안에 배치하지 않아야 한다.
- **FR-007**: 시스템은 각 Markdown 구조에 연결된 블록 주석과 선택 영역 주석의 대상, 표시, 편집 및 취소 동작을 유지해야 한다.
- **FR-008**: 시스템은 정확한 구조화가 불가능한 불완전한 Markdown 입력에서도 미리보기 오류로 전체 문서 표시 또는 주석 작업이 중단되지 않게 해야 한다.
- **FR-009**: 시스템은 원시 HTML과 활성 콘텐츠를 안전하게 처리하며, 미리보기에서 실행 가능한 콘텐츠를 새로 허용하지 않아야 한다.
- **FR-010**: 시스템은 표준 Markdown 예제와 실제 사용 문서에서 추출한 최소 재현 사례를 포함하는 버전 관리된 렌더링 품질 코퍼스를 제공해야 한다.
- **FR-011**: 품질 코퍼스의 각 사례는 입력 Markdown, 기대되는 HTML 구조 또는 의미, 그리고 해당되는 경우 주석 호환 기대 결과를 식별해야 한다.
- **FR-012**: 시스템은 품질 코퍼스 전체에 대해 자동 검증을 제공하고, 실패 시 사례와 불일치한 기대 구조를 식별해야 한다.
- **FR-013**: 시스템은 새로운 렌더링 결함이 발견되면 최소 재현 사례와 회귀 기대 결과를 품질 코퍼스에 추가할 수 있어야 한다.
- **FR-014**: 시스템은 기존 문서 열기, 목차, Mermaid, 링크 활성화 및 주석 내보내기 동작을 이 기능으로 인해 회귀시키지 않아야 한다.
- **FR-015**: 시스템은 AW의 패널 내 Markdown 미리보기에서 사용자가 주석 영역을 표시하거나 숨길 수 있게 해야 한다.
- **FR-016**: 시스템은 주석 영역을 숨긴 경우 그 영역이 차지하던 가로 공간을 미리보기 본문에 제공해야 한다.
- **FR-017**: 시스템은 주석 영역 표시 상태를 전환해도 현재 문서, 작성된 주석, 주석 수, 선택 영역 및 진행 중인 주석 작성·편집 상태를 보존해야 한다.
- **FR-018**: 시스템은 주석 영역의 표시 전환 제어에 현재 상태를 알 수 있는 접근 가능한 이름과 시각적 상태를 제공해야 한다.

### Key Entities

- **Markdown Rendering Fixture**: 하나의 Markdown 입력과 기능 범주, 기대되는 문서 의미 및 HTML 구조를 함께 정의한 품질 검증 사례.
- **Rendering Quality Corpus**: 목록, 블록, 인라인, 확장 문법, 잘못된 입력 및 주석 상호작용을 망라하는 검증 사례의 관리 집합.
- **Rendered Document Structure**: Markdown 입력에서 도출된 제목, 문단, 목록, 항목, 코드, 표, 인용문 등 사용자에게 표시되는 계층 관계.
- **Annotation Anchor**: 특정 문서 블록 또는 텍스트 범위에 주석을 연결하는 식별 정보로, 렌더링 품질 개선 후에도 대상 의미를 유지해야 한다.
- **Annotation Panel Visibility**: AW Markdown 미리보기에서 주석 목록과 관련 보조 내용을 표시할지 숨길지를 나타내는 현재 화면 상태.

## Constitution Alignment *(mandatory)*

- **Monorepo boundary**: Markdown 구조 해석과 품질 코퍼스는 `packages/markdown-annotation-core` 및 `packages/markdown-annotation-react`에 둔다. MA 앱은 이 패키지를 소비하는 화면·스토리 검증만 담당하며, 다른 앱에서 소비하지 않는 UI는 공유하지 않는다.
- **Frontend layering**: MA의 문서 미리보기 화면은 `pages/annotator`에 유지한다. 주석 상호작용은 기존 `features`와 `entities` 경계를 따른다. AW의 주석 영역 표시 상태는 기존 `features/worktree-workspace` 화면 상태에 둔다. 공용 Markdown 뷰어와 순수 해석 보조 로직은 해당 공유 패키지에 둔다.
- **Backend boundary**: 이 기능은 문서 표시와 주석 앵커 보존이 범위이므로 새 Tauri 명령, 저장소 또는 backend 변경을 요구하지 않는다.
- **Shared core vs UI**: 문서 구조 해석·품질 사례·기대 구조 비교는 순수 로직과 fixture 기반 검증을 우선한다. Annotator 전용 주석 제어 UI는 앱/뷰어에 유지한다.
- **Persistence and safety**: 사용자가 연 문서의 내용·경로 처리 정책을 변경하지 않는다. 활성 콘텐츠는 실행하지 않으며 주석 앵커는 다른 범위로 자동 재지정하지 않는다.
- **Documentation and Storybook**: `docs/markdown-rendering-quality.md`에 한국어 품질 기준과 검증 흐름을 Mermaid로 기록한다. 재사용 가능한 MarkdownViewer의 복합 목록, 주석 결합, 오류 복원 상태를 atomic design 분류에 맞춘 Storybook 사례로 추가한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 목록 이어쓰기, 빈 줄 포함 항목, 중첩 목록, 순서 목록 시작 번호를 포함한 최소 20개 품질 사례가 모두 기대한 문서 계층과 HTML 구조로 검증된다.
- **SC-002**: 품질 코퍼스에 포함된 CommonMark 핵심 문법 및 지원 GFM 확장 사례의 자동 검증 통과율은 100%다.
- **SC-003**: 복합 목록·표·코드·링크·인라인 서식을 포함한 최소 10개 주석 결합 사례에서 주석 대상과 편집·취소 흐름의 회귀는 0건이다.
- **SC-004**: 잘못되었거나 불완전한 Markdown 입력 최소 10개 사례에서 전체 미리보기 중단 또는 문서 외 주석 손실은 0건이다.
- **SC-005**: 2,000개 이상의 독립 문서 구조를 포함한 문서를 열 때 기존 미리보기 성능 기준을 만족하며, 품질 개선으로 사용자에게 보이는 지연이 증가하지 않는다.
- **SC-006**: 유지보수자는 품질 테스트 실패 시 한 번의 테스트 실행으로 실패한 fixture 이름과 기대한 구조를 식별할 수 있다.
- **SC-007**: 주석 유무와 관계없이 AW 패널 미리보기에서 사용자는 한 번의 명확한 조작으로 주석 영역을 보이거나 숨길 수 있으며, 전환 후 문서와 기존 주석의 손실은 0건이다.

## Assumptions

- v1의 호환 기준은 CommonMark 핵심 문법과 현재 제품이 제공하는 GFM 확장이다. MDX, 임의 플러그인 문법 및 특정 편집기 전용 확장은 범위 밖이다.
- 품질 코퍼스는 표준 예제를 참고하되 프로젝트에서 허용하는 라이선스·인용 범위 내에서 최소 재현 입력과 독자적인 기대 결과로 관리한다.
- 원시 HTML은 Markdown 호환성 범위로 별도 실행 지원하지 않으며, 현재의 안전한 미리보기 정책을 유지한다.
- 사용자에게 이미 제공 중인 블록 주석, 선택 영역 주석, 목차, Mermaid 및 링크 흐름은 호환성 기준선으로 간주한다.
- 외부에서 가져온 문서가 표준과 다른 관용 문법을 포함할 수 있으므로, 지원하지 않는 문법은 가능한 한 평문으로 안전하게 표시한다.
- 주석 영역은 AW Markdown 미리보기에서 기본적으로 표시되어 기존 사용자의 동작을 유지하며, 표시 상태의 장기 저장 여부는 이 기능 범위에 포함하지 않는다.
