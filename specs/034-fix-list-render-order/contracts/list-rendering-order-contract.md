# 목록 렌더링 순서 계약

`MarkdownViewer`가 최상위 목록을 렌더할 때 지켜야 하는 순서·구조 계약이다. 033의 시맨틱
계약(`ul`/`ol` 직접 자식은 항상 `li`)을 전제로 하며, 여기서는 **문서 순서 보존**을
추가로 규정한다.

## 입력 계약

- 렌더러는 `parseMarkdownToBlocks`가 산출한 `MarkdownBlock[]`을 **원문 순서 그대로**
  받는다. 호출자·렌더러는 이 배열을 재정렬하지 않는다.
- 최상위 목록 항목은 `type === "list-item"` 및 `parentId === undefined`로 식별한다.

## 출력 계약 (순서·구조)

**런 경계 정의**: 최상위 목록 항목(`parentId === undefined`)의 런은 **비-`list-item`
타입 블록(heading/paragraph/code/table/blockquote/hr)에 의해서만** 끊긴다. 두 최상위
항목 사이에 중첩 항목(`parentId` 있음)만 있으면 같은 런(같은 목록)이다.

| 입력 문서 형태 | 필수 렌더 결과 |
|---|---|
| 연속된 최상위 목록 항목(사이에 비-list-item 블록 없음) | 하나의 연속된 `ul`/`ol` |
| 최상위 항목 A(중첩 A1 포함) 다음 최상위 항목 B (`- A\n  - A1\n- B`) | 하나의 `ul`에 A(중첩 A1)와 B. B는 별도 목록이 아님 |
| 비-list-item 블록(제목/문단/코드/표/인용/hr)으로 분리된 두 최상위 목록 | 두 개의 별도 목록. 각 목록은 자신의 원문 위치에 렌더 |
| 목록 → 제목 → 목록 | 첫 목록, 그 뒤 제목, 그 뒤 두 번째 목록 순서 |
| 런 내부 비순서↔순서 전환 | 같은 런이라도 `ul`과 `ol[start]`로 분리 |
| 부모 항목 아래 중첩 목록 | 부모 `li` 내부에 중첩된 `ul`/`ol`, 부모의 뒤 형제 항목은 원문 순서 유지 |

### 핵심 불변식

1. **순서 보존**: 렌더 결과에서 임의의 블록 B는, 원문에서 B보다 앞선 어떤 블록보다도
   먼저 나타나지 않는다.
2. **병합 금지**: 사이에 비-`list-item` 블록이 하나라도 있으면 두 목록은 하나로
   합쳐지지 않는다.
3. **인접 유지**: 사이에 비-`list-item` 블록이 없는 최상위 목록 항목은 하나의 목록으로
   유지된다(사이의 중첩 항목은 경계가 아님).
4. **종류·번호 유지**: `ordered`/`orderedStart`는 원문 의미대로 표현된다.
5. **주석 앵커 안정**: 각 목록 항목의 `data-block-id`, `data-block-type`, source 범위
   속성은 실제 시맨틱 `li`에 부착되며, 순서 보존이 앵커 대상을 바꾸지 않는다.
6. **안정적 key**: 렌더된 각 목록 항목은 고유 `key`(블록 id)를 가져 재조정이 안정적이다.
7. **단일 마커**: 항목당 마커는 하나만 표시한다. 커스텀 마커(`-`/`N.`/체크박스)를 쓰므로
   네이티브 목록 마커는 `list-style: none`으로 끈다(중복 `• -`, `1. 1.` 금지).
8. **순서 번호 증가**: 순서 목록 표시 번호는 `orderedStart + 항목 인덱스`로 증가한다.

## 검증 대상 시나리오(계약 테스트)

- CT-1: `- Apple` / 문단 / `- Banana` → 렌더 텍스트 순서 Apple < Middle < Banana, 목록 2개.
- CT-2: `## Setup`+목록 / `## Usage`+목록 → 각 목록이 자기 제목 뒤에, Usage 제목이 Usage
  목록 항목보다 앞.
- CT-3: 비순서 목록 다음 `3.`으로 시작하는 순서 목록(사이 문단 없음/있음) → 각각 별도
  목록, 순서 목록은 `start=3`.
- CT-4: 부모/자식 중첩 + 부모의 뒤 형제 → 중첩 유지 및 형제 순서 유지.
- CT-5: 2,000개 목록 항목 렌더가 성능 예산(<2,000ms) 내.
- CT-6: `- A\n  - A1\n- B`(중첩 항목이 두 최상위 항목 사이에 위치) → A·B가 **하나의**
  `ul`로 유지되고 A 안에 A1이 중첩된다(오분리로 두 목록이 되지 않음).
- CT-7: 렌더된 목록 항목에 React key 경고가 발생하지 않는다.
- CT-8: 두 개의 분리된 목록을 가진 문서에서, 두 번째 목록의 항목에 단 주석이 순서 보존
  이후에도 해당 항목에 그대로 연결되고 표시된다(FR-006).
- CT-9: 목록이 서로 다른 H1 챕터에 분산된 문서에서, 각 목록이 자기 챕터 뒤에 렌더되고
  TaskSummary가 각 챕터의 올바른 위치에 유지된다.
- MK-1: 순서 목록 마커가 시작값 반복이 아니라 `1. 2. 3.`으로 증가한다(FR-009).
- MK-2: 커스텀 시작 번호(`3.`)에서 `3. 4. …`로 증가한다(FR-009).
- MK-3: 비순서 항목마다 커스텀 마커가 정확히 하나만 존재하고, `styles.css`가
  `list-style: none`으로 네이티브 마커를 꺼 중복을 막는다(FR-008).
