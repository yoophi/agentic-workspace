# Feature Specification: Kiro CLI Session Resume

**Feature Branch**: `036-kiro-session-resume`

**Created**: 2026-08-25

**Status**: Draft

**Input**: User description: "Kiro CLI 세션 재개 지원. AW의 \"기존 세션 재사용\" 목록에 Kiro CLI 세션이 나타나고 선택해 재개할 수 있도록 한다. Kiro는 ~/.kiro/sessions/cli/에 <session-id>.json(메타)과 <session-id>.jsonl(대화 로그)을 남기며, ACP loadSession:true와 session/load를 지원한다. 현재는 provider_kind_for에서 None이라 목록에 뜨지 않는다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 워크트리에서 이전 Kiro 대화 이어가기 (Priority: P1)

작업자가 어제 Kiro CLI로 특정 워크트리에서 리팩터링 작업을 하다 중단했다. 오늘 AW에서 같은 워크트리를 열고 Kiro CLI를 고른 뒤 "기존 세션 재사용"을 선택하면, 그 워크트리에서 진행했던 대화가 목록에 나타난다. 하나를 고르고 시작하면 이전 맥락이 살아 있는 상태로 대화를 이어간다.

**Why this priority**: 이 기능의 존재 이유 그 자체다. Codex·Claude Code 사용자는 이미 이 흐름을 쓰고 있고, Kiro만 빠져 있어 같은 작업을 새 세션으로 다시 설명해야 한다.

**Independent Test**: Kiro CLI로 임의 디렉토리에서 대화를 한 번 만든 뒤, AW에서 그 디렉토리를 작업 디렉토리로 열고 Kiro CLI + 기존 세션 재사용을 선택해 해당 대화가 목록에 뜨고 재개되는지 확인한다. 이것만 구현해도 사용자에게 가치가 전달된다.

**Acceptance Scenarios**:

1. **Given** 작업자가 디렉토리 D에서 Kiro CLI 대화를 남긴 상태이고 AW의 작업 디렉토리가 D일 때, **When** Kiro CLI를 선택하고 "기존 세션 재사용"으로 전환하면, **Then** 그 대화가 세션 목록에 나타난다.
2. **Given** 세션 목록에서 대화 하나를 선택한 상태에서, **When** 실행을 시작하면, **Then** 새 대화가 아니라 선택한 대화가 이어지며 이전 맥락을 참조한 응답을 받는다.
3. **Given** 작업 디렉토리 D에 Kiro 세션이 하나도 없을 때, **When** "기존 세션 재사용"으로 전환하면, **Then** 빈 목록임을 알리는 안내가 표시되고 새 세션으로 시작할 수 있다.

---

### User Story 2 - 여러 세션 중 올바른 것 식별하기 (Priority: P2)

한 워크트리에서 여러 주제로 대화한 작업자가 목록에서 원하는 세션을 골라야 한다. 각 항목에 대화 제목과 마지막 활동 시각이 보여서 어느 것이 무슨 작업이었는지 구분할 수 있다.

**Why this priority**: P1이 동작해도 세션이 여러 개면 식별 정보 없이는 고르기 어렵다. 다만 세션이 하나뿐인 경우 P1만으로도 가치가 성립하므로 P2다.

**Independent Test**: 같은 디렉토리에서 서로 다른 주제의 Kiro 대화를 2개 이상 만든 뒤, 목록에서 제목과 시각으로 구분되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 한 디렉토리에 서로 다른 주제의 Kiro 세션이 여러 개 있을 때, **When** 세션 목록을 보면, **Then** 각 항목에 그 대화의 제목과 마지막 활동 시각이 표시된다.
2. **Given** 세션 목록이 표시된 상태에서, **When** 항목 순서를 보면, **Then** 최근 활동한 세션이 먼저 보인다.
3. **Given** 제목이 아직 정해지지 않은 세션이 있을 때, **When** 목록을 보면, **Then** 제목 자리에 식별 가능한 대체 표기가 나타나고 항목이 사라지지 않는다.

---

### User Story 3 - 대화가 없는 빈 세션 걸러내기 (Priority: P3)

Kiro는 연결만 맺고 대화가 오가지 않은 경우에도 세션 기록을 남긴다. 도구가 연결을 시험하거나 사용자가 시작만 하고 아무것도 묻지 않고 닫은 경우가 여기에 해당한다. 작업자는 목록에서 실제로 내용이 있는 대화만 보고 싶다.

**Why this priority**: 목록 품질 문제다. 없으면 이어갈 내용이 없는 항목이 섞이지만 P1·P2의 가치를 막지는 않는다.

**Independent Test**: 대화 없이 연결만 맺은 세션을 만든 뒤(예: 세션을 시작하고 아무 프롬프트도 보내지 않고 종료) 목록에 그 항목이 나타나지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 저장소에 내용이 있는 대화와 대화 기록이 비어 있는 세션이 함께 있을 때, **When** 세션 목록을 보면, **Then** 내용이 있는 대화만 표시된다.
2. **Given** 대화가 진행 중이라 아직 제목이 정해지지 않았지만 주고받은 내용은 있는 세션이 있을 때, **When** 목록을 보면, **Then** 그 세션은 제외되지 않고 표시된다.

---

### Edge Cases

- **세션 메타 파일이 손상되었거나 일부만 기록된 경우**: 해당 항목만 건너뛰고 나머지 목록은 정상 표시된다. 목록 전체가 실패하지 않는다.
- **Kiro를 한 번도 쓰지 않아 세션 저장소 자체가 없는 경우**: 오류가 아니라 빈 목록으로 처리된다.
- **세션이 기록된 작업 디렉토리가 삭제되었거나 현재 워크트리와 다른 경우**: 현재 작업 디렉토리 기준 필터에서 제외된다.
- **선택한 세션을 Kiro가 더 이상 불러오지 못하는 경우**(내부적으로 정리되었거나 형식이 바뀜): 재개 실패 사유가 사용자에게 전달되고, 새 세션으로 시작할 수 있는 상태로 남는다.
- **세션 수가 많은 경우**(수십 개 이상): 목록 조회가 체감 지연 없이 끝난다.
- **대화 로그가 매우 큰 세션**(수백 KB 이상): 목록 표시를 위해 전체 로그를 읽어 들이지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 Kiro CLI가 로컬에 남긴 대화 세션을 조회해 "기존 세션 재사용" 목록에 제공해야 한다.
- **FR-002**: 시스템은 현재 작업 디렉토리에서 진행된 세션만 목록에 포함해야 한다(다른 provider와 동일한 범위 규칙).
- **FR-003**: 각 세션 항목은 대화 제목, 생성 시각, 마지막 활동 시각을 포함해 사용자가 세션을 식별할 수 있어야 한다.
- **FR-004**: 사용자는 목록에서 세션 하나를 선택해 그 대화를 이어서 진행할 수 있어야 한다.
- **FR-005**: 재개된 대화는 이전 맥락을 유지해야 한다(새 대화로 시작되지 않는다).
- **FR-006**: 시스템은 읽을 수 없거나 형식이 어긋난 세션 기록을 건너뛰고 나머지 목록을 정상 제공해야 한다.
- **FR-007**: 시스템은 대화 기록이 비어 있는 세션을 목록에서 제외해야 한다. 내용이 있으나 제목이 아직 없는 세션은 제외하지 않는다.
- **FR-008**: 세션 저장소가 존재하지 않는 경우 시스템은 오류 대신 빈 목록을 반환해야 한다.
- **FR-009**: 세션 재개가 실패하면 시스템은 실패 사실과 사유를 사용자에게 알리고, 새 세션으로 진행할 수 있는 상태를 유지해야 한다.
- **FR-010**: 시스템은 목록 표시에 필요한 정보만 읽어야 하며, 대화 로그 전체를 읽어 들이지 않아야 한다.

### Key Entities

- **Kiro 세션 기록**: Kiro CLI가 로컬에 남긴 대화 한 건. 식별자, 진행된 작업 디렉토리, 대화 제목, 생성 시각, 마지막 활동 시각, 생성 경위(사용자 시작 / 내부 서브에이전트)를 가진다.
- **Provider 세션 요약**: AW가 여러 agent의 세션을 동일한 형태로 다루기 위한 표현. 어떤 agent의 세션인지, 식별자, 작업 디렉토리, 제목, 시각 정보를 담는다. Kiro 세션 기록은 이 표현으로 변환되어 기존 목록 흐름에 합류한다.

## Constitution Alignment *(mandatory)*

- **Monorepo boundary**: `apps/agentic-workbench`(Tauri 백엔드의 provider 세션 조회 경로) 범위. 세션 저장소 해석은 AW 전용 관심사이므로 `crates/*`로 공유하지 않는다. 다른 앱과의 공유는 의도적으로 배제한다.
- **Frontend layering**: 신규 UI 없음. 기존 "기존 세션 재사용" 목록이 provider 무관하게 동작하므로 프론트 변경은 원칙적으로 불필요하다. 변경이 필요해지면 기존 `features/agent-run` 슬라이스 범위 안에서 처리한다.
- **Backend boundary**: `domain`에는 provider 종류 식별과 순수 데이터 타입만 둔다. 파일 시스템 접근과 Kiro 기록 해석은 `infrastructure`의 provider 세션 저장소 어댑터에 둔다. `domain`은 파일 시스템·Tauri에 의존하지 않는다. Tauri 명령은 입력 검증만 하고 조회 로직을 갖지 않는다.
- **Shared core vs UI**: 공유 패키지 신설 없음. Kiro 기록 해석은 단일 앱 관심사이며, 두 번째 소비자가 생기기 전까지 공유하지 않는다.
- **Persistence and safety**: 세션 저장소 루트는 사용자 홈 아래 Kiro 경로로 한정하고, 해당 루트를 벗어나는 경로는 읽지 않는다. 세션 목록은 현재 작업 디렉토리 범위로 제한해 다른 프로젝트의 대화가 노출되지 않도록 한다. 조회는 읽기 전용이며 Kiro 세션 파일을 수정하지 않는다.
- **Documentation and Storybook**: Storybook 대상 없음(신규 UI 없음). Kiro 세션 재개 지원 사실과 제약을 `docs/*.md`에 반영한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Kiro CLI로 대화를 남긴 워크트리에서, 작업자가 그 대화를 목록에서 찾아 재개하기까지 별도 안내 없이 30초 안에 완료한다.
- **SC-002**: 재개한 대화에서 이전 맥락을 참조하는 질문에 대해, 사용자가 맥락을 다시 설명하지 않고도 올바른 답을 받는다.
- **SC-003**: 세션이 30건 이상 쌓인 저장소에서도 목록이 2초 안에 표시된다.
- **SC-004**: 손상된 세션 기록이 섞여 있어도 나머지 세션 100%가 목록에 정상 표시된다.
- **SC-005**: 목록에 표시되는 항목 중 이어갈 내용이 없는 빈 세션의 비율이 0%다.

## Assumptions

- **세션 저장소 위치**: Kiro CLI는 사용자 홈 아래 고정 경로에 세션을 남긴다. 이 경로는 Kiro의 구현 세부사항이므로, 위치가 바뀌면 조회가 실패할 수 있고 그 경우 빈 목록으로 처리한다.
- **빈 세션 제외를 기본값으로 채택**: 세션 기록에는 생성 경위를 나타내는 값이 함께 저장되지만, 실측 결과 사용자가 터미널에서 직접 시작한 대화에도 동일한 값이 붙어 있어 "사람이 시작한 세션"을 가려내는 근거로 쓸 수 없다(plan 단계 조사 결과, `research.md` 참조). 대신 대화 기록이 비어 있는지를 기준으로 삼는다. 실측에서 빈 세션은 모두 연결만 맺고 끝난 것이었고, 이어갈 내용이 없으므로 목록에서 제외하는 것이 사용자에게 유용하다.
- **재개는 Kiro가 제공하는 세션 불러오기 기능에 의존**: Kiro는 세션 불러오기를 지원한다고 스스로 알린다. 실제 재개 가능 여부는 Kiro 쪽 상태에 달려 있으므로, 실패를 정상 경로로 처리한다(FR-009).
- **목록 범위 규칙은 기존 provider와 동일**: 작업 디렉토리 기준 필터링, 최근 활동 우선 정렬 등 기존 세션 목록의 규칙을 그대로 따르며 Kiro만을 위한 별도 규칙을 만들지 않는다.
- **모델·effort 선택과의 관계**: 세션 재개 시 적용되는 모델·effort는 기존 실행 설정 흐름을 따른다. 재개된 대화에서 이전 세션의 모델 설정이 유지되는지는 Kiro의 동작에 달려 있으며, 이 기능의 범위는 "세션을 찾아 이어가는 것"까지다.
- **대화 로그 형식에 의존하지 않음**: 목록 표시에 필요한 정보는 메타 기록에서 얻는다. 대화 로그 형식이 바뀌어도 목록 기능은 영향받지 않는다.
