## 배경

043까지 화면은 네트워크 경로(HTTP 호출·WS 구독)의 클라이언트가 됐지만, Workbench 서버는 여전히 데스크톱 앱 프로세스 **안에서** 돈다. 그래서 앱을 끄면 run·교환·orchestration이 함께 끝나고, 앱 없이 같은 run을 볼 방법이 없다. 이 증분은 서버를 **별도 프로세스**로 떼어 내 앱이 종료돼도 작업이 계속되게 하고, 한 사용자·데이터 디렉터리에 서버가 정확히 하나(단일 writer)만 쓰게 한다.

## 5단계 완료 기준과 이 증분의 범위 (추적 표)

설계 문서(`docs/client-server-architecture-research.md` §5, "server process와 native process 생명주기")의 5단계 완료 기준을 그대로 추적한다. **이 표의 "다음 증분" 항목은 044가 끝나도 미완료다.**

| 기준 | 내용 | 044 | 남는 것(다음 증분) |
|---|---|---|---|
| (a) 종료 뒤 지속 | 데스크톱 프로세스가 실제로 종료된 뒤에도 같은 run을 조회·관찰·취소 | **서버 쪽 실행 유지와 조회·관찰·취소**: 앱 종료가 run을 취소하지 않음, 시작한 turn·대기열 prompt·orchestration 알림은 서버가 끝까지 실행, 앱 없이 사용자 소유 자격 증명의 네트워크 클라이언트로 조회·관찰·취소 | CLI(6단계)로 같은 흐름, 다시 연 데스크톱이 남은 작업대에 다시 붙는 화면, 교환 전달의 서버 소유(오늘은 데스크톱 UI가 라우팅·전송) |
| (b) 독립 composition root | 서버가 데스크톱과 무관하게 스스로 조립·기동 | **전부** | — |
| (c) 단일 writer·생명주기 | 짧은 시작 잠금과 서버가 실행 내내 쥐는 소유 잠금, 사용자만 읽는 원자적 서버 안내 파일, 인증된 버전 확인, 준비 상태, 시작 복구, 서빙→비우기→정지 상태, 유휴·임대 정책 | **전부** | — |
| (d) 프로세스 트리 가두기 | 모든 agent·터미널·Git 자식 프로세스를 공통 감독자로, 정상 종료 → 강제 트리 종료 → 회수 | 서버 종료 때 자식 정리는 오늘 수준 유지 | 공통 감독자, 플랫폼별 트리 가두기, 강제 종료 뒤 잔여 자식 정리 |
| (e) 데이터 이전·복원·호환 | 기존 앱 데이터를 서버가 그대로 쓰거나 한 번 가져오기, 백업·복원, 저장 형식 호환 확인 | 서버가 오늘의 앱 데이터 디렉터리를 **같은 형식으로** 연다. 버전 확인에 저장 형식 버전을 싣고, 모르는 형식이면 거절 | 백업·복원, 단계적 이전, 이전 실패 되돌리기 |
| (f) 배포·업데이트 | 설치본에 서버 실행 파일 포함, 서명·공증, 버전별 실행 캐시, 업데이트 때 활성 run 보존·서버 quiesce | 개발·디버그 빌드에서 서버 실행 파일을 찾는 규칙만 | 설치본 포함·서명·공증, 버전별 캐시, 업데이트 preflight |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 앱을 꺼도 run이 계속되고, 앱 없이 볼 수 있다 (Priority: P1)

사용자가 agent run을 시작한 뒤 데스크톱 앱을 종료한다. run은 끝나지 않고 계속 돈다. 사용자(또는 사용자 계정의 다른 도구)는 앱 없이 사용자 소유 자격 증명으로 서버에 붙어 그 run의 상태를 조회하고, 출력을 이어 받고, 취소할 수 있다.

**Why this priority**: 5단계의 핵심 약속(a)이다. 서버를 떼어 내는 이유가 이것이다.

**Independent Test**: 서버를 띄우고 데스크톱에서 run을 시작한 뒤 데스크톱 프로세스를 실제로 끝낸다. 서버 안내 파일로 서버를 찾아 사용자 소유 자격 증명으로 붙어 run을 조회·구독·취소한다.

**Acceptance Scenarios**:

1. **Given** 데스크톱에서 시작한 진행 중 run, **When** 데스크톱 앱을 종료한다, **Then** run은 취소되지 않고 계속 출력을 낸다.
2. **Given** 데스크톱이 없는 상태, **When** 사용자 소유 자격 증명으로 서버에 붙어 작업대·run 목록을 조회한다, **Then** 데스크톱이 연 작업대와 그 run이 보인다.
3. **Given** 같은 상태, **When** 그 run의 이벤트를 구독한다, **Then** 이미 보낸 출력은 재생되고 새 출력이 이어서 도착한다.
4. **Given** 같은 상태, **When** 그 run을 취소한다, **Then** run이 취소되고 agent 프로세스가 끝난다.
5. **Given** 사용자 소유 자격 증명이 아닌 자격 증명(다른 창 주체, agent 주체, 만료·폐기된 토큰), **When** 같은 조작을 한다, **Then** 서버 판정으로 거절된다.

### User Story 2 - 데스크톱은 서버를 찾거나 띄워 붙는다 (Priority: P1)

사용자가 앱을 연다. 앱은 이미 떠 있는 서버를 서버 안내 파일로 찾아 붙거나, 없으면 서버를 띄운 뒤 준비될 때까지 기다려 붙는다. 창마다 서버가 발급한 짧은 토큰으로 연결하고, 화면 동작은 043과 같다. 창을 닫으면 그 창의 토큰이 폐기되고 그 창의 작업대가 닫힌다(오늘과 같은 창 닫기 의미).

**Why this priority**: 데스크톱이 서버 프로세스를 쓰지 못하면 어떤 기능도 쓸 수 없다.

**Independent Test**: 서버가 없는 상태에서 앱을 열어 서버가 한 번만 떠서 준비되는지, 떠 있는 상태에서 앱을 열어 새로 띄우지 않고 붙는지 확인한다. 창을 열어 run을 시작하고, 창을 닫아 그 작업대가 닫히는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 서버가 없음, **When** 앱을 연다, **Then** 서버가 하나 떠서 준비된 뒤 창이 연결된다.
2. **Given** 서버가 떠 있음, **When** 앱을 연다, **Then** 새 서버를 띄우지 않고 기존 서버에 붙는다.
3. **Given** 앱 두 개가 거의 동시에 서버를 띄우려 함, **When** 둘 다 시작 절차를 밟는다, **Then** 서버는 하나만 떠서 둘 다 그 서버에 붙는다.
4. **Given** 연결된 창, **When** 창을 닫는다, **Then** 그 창의 토큰으로는 더 호출·구독할 수 없고 그 창의 작업대와 run이 닫힌다.
5. **Given** 연결된 창, **When** 앱 전체를 종료한다, **Then** 창의 작업대·run은 닫히지 않는다(US1). 앱이 쥔 임대만 풀린다.
6. **Given** 서버를 띄울 수 없음(실행 파일 없음, 기동 실패, 버전 불일치), **When** 앱을 연다, **Then** 창은 서버에 연결할 수 없다는 상태와 이유를 보여 주고 다시 시도할 수 있다. 앱이 자기 안에서 몰래 두 번째 writer를 띄우지 않는다.

---

### User Story 3 - 한 데이터 디렉터리에 서버는 하나만 쓴다 (Priority: P1)

같은 사용자·채널·프로필·데이터 디렉터리에 대해 서버는 동시에 하나만 데이터를 쓴다. 두 번째 서버를 띄우려 하면 거절되고 기존 서버 위치를 알려 준다. 서버가 비정상 종료돼 잠금·안내 파일이 남아도, 다음 시작이 이를 알아보고 복구한다. 서버 안내 파일과 자격 증명은 그 사용자만 읽을 수 있다.

**Why this priority**: 단일 writer가 깨지면 데이터가 손상된다(c).

**Independent Test**: 같은 데이터 디렉터리로 서버 둘을 띄워 하나만 서빙하는지 본다. 서버를 강제로 죽인 뒤 다시 띄워 남은 잠금·안내 파일을 복구하는지 본다. 안내 파일 권한을 확인한다.

**Acceptance Scenarios**:

1. **Given** 서빙 중인 서버, **When** 같은 데이터 디렉터리로 서버를 하나 더 띄운다, **Then** 두 번째는 데이터를 열지 않고 "이미 서버가 있음"과 기존 위치를 알린 뒤 끝난다.
2. **Given** 강제 종료로 남은 안내 파일, **When** 서버를 띄운다, **Then** 남은 안내 파일이 죽은 서버의 것임을 알아보고 새 안내 파일로 바꾼다.
3. **Given** 다른 데이터 디렉터리(다른 프로필·채널), **When** 서버를 띄운다, **Then** 서로의 잠금·안내 파일을 가로채지 않고 따로 뜬다.
4. **Given** 서버 안내 파일, **When** 권한을 본다, **Then** 소유 사용자만 읽고 쓸 수 있다.
5. **Given** 안내 파일이 가리키는 끝점, **When** 버전 확인 없이 또는 다른 서버 인스턴스를 가리키는 안내 파일로 붙는다, **Then** 클라이언트는 인증된 버전 확인에서 불일치를 알아보고 붙지 않는다.

### User Story 4 - 서버는 스스로 비우고 멈춘다 (Priority: P2)

서버는 서빙 → 비우기 → 정지 상태를 가진다. 비우는 동안 새 변경은 정해진 오류로 거절되고, 받아들인 호출은 끝까지 간다. 활성 작업(진행 중 run, 권한 대기, orchestration 작업, 판정 전 변경)이나 유효한 클라이언트 임대가 있으면 유휴 종료하지 않는다. 사용자가 정지를 요청하면 활성 작업이 있을 때 거절하고, "끝날 때까지 기다림"과 "강제 취소"를 명시적으로 고를 수 있다.

**Why this priority**: 독립 서버는 스스로 수명을 정해야 한다. 없으면 서버가 영원히 남거나 작업 중에 사라진다.

**Independent Test**: 임대·활성 작업이 없을 때 유휴 시간이 지나 서버가 끝나는지, 활성 run이 있을 때 끝나지 않는지, 정지 요청의 세 방식이 각각 정해진 대로 동작하는지 본다.

**Acceptance Scenarios**:

1. **Given** 임대·활성 작업 없음, **When** 유휴 시간이 지난다, **Then** 서버가 비우고 멈추며 안내 파일을 지운다.
2. **Given** 진행 중 run, 임대 없음, **When** 유휴 시간이 지난다, **Then** 서버는 멈추지 않는다.
3. **Given** 진행 중 run, **When** 기본 정지를 요청한다, **Then** 활성 작업이 있어 거절된다.
4. **Given** 진행 중 run, **When** "기다림" 정지를 요청한다, **Then** 새 변경을 거절하며 run이 끝날 때까지 기다린 뒤 멈춘다.
5. **Given** 진행 중 run, **When** "강제" 정지를 요청한다, **Then** run을 취소하고 멈춘다.
6. **Given** 비우는 중, **When** 새 변경 호출이 온다, **Then** 정해진 "비우는 중" 오류로 거절된다(적용되지 않음). 조회는 계속 답한다.

### User Story 5 - 종료와 멱등성이 경합하지 않는다 (Priority: P2)

작업대를 닫는 동안 그 작업대의 변경 호출이 늦게 끝나도, 닫힌 작업대의 멱등 기록이 되살아나지 않는다. 닫은 뒤 같은 키로 재시도하면 "작업대 없음"이 되고 효과를 다시 적용하지 않는다(#207).

**Why this priority**: 독립 서버의 종료·정지는 작업대 닫기를 자주 거친다. 이 경합이 남으면 닫힌 작업대의 결과가 재시도에 되돌아온다.

**Independent Test**: 작업대 닫기와 그 작업대의 변경 호출 완료 순서를 강제로 뒤집는 시험으로, 닫은 뒤 재시도가 "작업대 없음"인지 본다.

**Acceptance Scenarios**:

1. **Given** 작업대의 변경 호출이 진행 중, **When** 작업대를 닫고 그 뒤에 호출이 성공으로 끝난다, **Then** 그 성공은 멱등 기록에 남지 않는다.
2. **Given** 위 상태, **When** 같은 키로 재시도한다, **Then** "작업대 없음"으로 거절되고 효과는 다시 적용되지 않는다.

### Edge Cases

- 앱이 서버를 띄우는 중에 다른 앱이 같은 데이터 디렉터리로 띄운다: 시작 잠금이 하나만 통과시키고, 다른 쪽은 준비된 서버에 붙는다.
- 서버가 준비되기 전에 시작 대기 시간이 지난다: 앱은 이유를 보여 주고 다시 시도할 수 있다. 반쯤 뜬 서버가 남으면 다음 시작이 복구한다.
- 서버가 앱이 붙어 있는 중에 재기동한다(새 세대): 043의 세대 변경 규칙(창 다시 불러오기)대로 다시 맞춘다. 앱이 서버를 다시 찾는다.
- 안내 파일은 있지만 가리키는 프로세스가 다른 프로그램(재사용된 프로세스 번호)이다: 프로세스 번호만으로 판단하지 않고, 인증된 버전 확인으로 서버 인스턴스를 확인한다.
- 앱이 종료되는 도중 창이 닫힌다: 앱 종료 절차에서는 창 닫기의 작업대 닫기를 하지 않는다(US1). 사용자가 창 하나만 닫을 때만 작업대를 닫는다.
- 앱이 강제로 죽는다(임대를 풀지 못함): 임대는 만료 시간이 있어 서버가 결국 임대를 거둔다.
- 앱 없이 남은 작업대를 사용자 소유 자격 증명으로 닫는다: 그 작업대의 run이 취소된다.
- 오래된 서버 실행 파일이 새 저장 형식의 데이터 디렉터리를 연다: 버전 확인·시작 검사에서 거절하고 데이터를 건드리지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**독립 서버(composition root)**

- **FR-001**: 서버는 데스크톱과 무관하게 스스로 조립·기동하는 별도 실행 파일이다. Workbench 런타임, 네트워크 끝점, agent가 쓰는 MCP 끝점을 모두 이 프로세스가 연다.
- **FR-002**: 서버는 데이터 디렉터리(오늘의 앱 데이터 디렉터리와 같은 위치·형식이 기본)를 입력으로 받아 연다. 채널·프로필을 구분해 서로 다른 데이터 디렉터리를 쓸 수 있다.
- **FR-003**: agent 실행에 MCP 연결 정보를 넣는 일은 창과 무관하게 서버가 한다. 데스크톱 창이 없어도 run 시작에 MCP 연결이 붙는다.
- **FR-004**: 창 제목 요청처럼 데스크톱 표현에 닿는 결과는 서버가 창에 직접 넣지 않는다. 데스크톱이 구독으로 받아 스스로 적용한다(창 제목, 메뉴 동기화).

**단일 writer·발견**

- **FR-005**: 같은 OS 사용자·채널·프로필·정규화한 데이터 디렉터리에 대해 데이터를 쓰는 서버는 동시에 하나다. 서버는 실행 내내 소유 잠금을 쥐고, 쥐지 못하면 데이터를 열지 않고 끝난다.
- **FR-006**: 서버 시작 절차는 소유 잠금과 다른 짧은 시작 잠금으로 직렬화한다. 동시에 시작하려는 클라이언트 중 하나만 서버를 띄우고, 나머지는 그 서버가 준비되기를 기다려 붙는다.
- **FR-007**: 준비된 서버는 소유 사용자만 읽고 쓸 수 있는 서버 안내 파일을 원자적으로 쓴다. 안내 파일에는 끝점, 서버 인스턴스 식별자, 세대, 서버·프로토콜·저장 형식 버전, 사용자 소유 자격 증명(또는 그 위치)이 있다. 서버가 멈추면 안내 파일을 지운다.
- **FR-008**: 클라이언트는 안내 파일을 믿기 전에 인증된 버전 확인을 한다. 안내 파일의 인스턴스 식별자와 서버가 답한 식별자가 다르거나, 프로토콜·저장 형식을 지원하지 않으면 붙지 않는다.
- **FR-009**: 서버 시작은 남은 잠금·안내 파일(비정상 종료의 흔적)을 알아보고 복구한다. 살아 있는 서버의 것인지는 프로세스 번호만이 아니라 잠금 소유와 인증된 버전 확인으로 판단한다.
- **FR-010**: 서버는 준비 상태를 알린다. 저장소를 열고 시작 복구(판정 전 변경의 판정 등)를 마치고 끝점을 연 뒤에만 준비다.

**자격 증명·권한**

- **FR-011**: 데스크톱은 안내 파일의 사용자 소유 자격 증명으로 서버에 창별 토큰을 요청한다. 토큰은 창 주체(`desktop:window:<label>:<incarnation>`)와 창의 WebView 출처에 묶이고 짧게 산다(043과 같은 갱신 규칙).
- **FR-012**: 창을 닫으면 데스크톱이 서버에 그 창 주체의 토큰·이벤트 표 폐기와 작업대 닫기를 요청한다. 폐기 뒤 그 창의 토큰으로 호출·구독하면 거절된다.
- **FR-013**: 사용자 소유 자격 증명을 가진 클라이언트(소유자 주체)는 데스크톱이 없어도 모든 작업대·run을 조회·구독하고, 작업대를 닫고 run을 취소할 수 있다. 창 주체·agent 주체는 오늘처럼 자기 작업대만 다룬다.
- **FR-014**: 서버 쪽 창 주체 등록(incarnation)은 서버가 관리한다. 데스크톱은 창을 만들 때 incarnation을 서버에 등록하고, 닫을 때 그 incarnation만 거둔다(043의 늦은 정리·같은 label 재개 규칙 유지).

**데스크톱 thin client**

- **FR-015**: 데스크톱은 자기 프로세스 안에서 Workbench 런타임을 열지 않는다(기본 모드). 서버 소유 조회·변경·구독은 모두 서버 끝점을 거친다.
- **FR-016**: 앱 내부 호환 경로(창 label로 작업대를 정해 앱 안의 런타임을 직접 부르는 command)와 네이티브 삽입 전달은 기본 모드에서 쓰지 않는다. 서버를 찾거나 띄우지 못하면 호환 경로로 대체하지 않고 연결 실패 상태를 보여 준다.
- **FR-017**: 개발·시험용 **embedded 모드**를 명시적 설정으로만 켤 수 있다. 이 모드는 오늘(043)처럼 앱 안에서 런타임을 연다. 같은 데이터 디렉터리의 소유 잠금을 똑같이 잡아, 외부 서버와 동시에 쓰지 못한다. embedded 모드와 그 호환 경로는 8단계에서 지운다.
- **FR-018**: 데스크톱 앱 종료는 앱이 쥔 클라이언트 임대만 푼다. 창의 작업대·run을 닫지 않는다. 사용자가 창 하나를 닫을 때만 그 창의 작업대를 닫는다.
- **FR-019**: 데스크톱 표현 상태(appearance, 창 상태, workspace layout)는 데스크톱에 남는다.

**생명주기**

- **FR-020**: 서버 상태는 서빙 → 비우기 → 정지다. 비우는 동안 새 변경은 "비우는 중" 오류로 거절하고(적용 안 됨), 받아들인 호출은 끝까지 가며, 조회는 계속 답한다. 비우는 동안 서버는 살아 있지만 준비 상태가 아니다.
- **FR-021**: 클라이언트 임대: 붙은 클라이언트(데스크톱 앱)는 만료 시간이 있는 임대를 잡고 갱신한다. 임대가 없고 활성 작업(진행·예약된 run, 권한 대기, orchestration 작업, 판정 전 변경)도 없으면 유휴 시간이 지난 뒤 서버가 스스로 비우고 멈춘다.
- **FR-020a**: 화면이 이미 전달 확인한 교환 prompt를 대기열에서 지우거나 버리면 서버에 전달 포기를 알려, 그 교환이 활성 작업으로 남아 "기다림" 정지를 막지 않게 한다. 교환 prompt는 즉시 전송(steer)으로 보내지 않는다(교환 소비가 기록되지 않는다).
- **FR-022**: 정지 요청은 세 방식이다. 기본은 활성 작업이 있으면 거절한다. "기다림"은 비운 뒤 활성 작업이 끝나면 멈춘다. "강제"는 명시적으로 작업대를 모두 닫아(run 취소) 멈춘다. 정지 요청은 소유자 주체만 할 수 있다.
- **FR-023**: 운영체제 종료 신호(정상 종료 요청)는 "강제" 정지와 같은 절차를 제한 시간 안에 밟는다.

**종료·멱등성(#207)**

- **FR-024**: 닫힌 작업대 범위의 멱등 기록은 되살아나지 않는다. 작업대가 닫힌 뒤 끝난 변경 호출의 결과는 기록하지 않고, 닫은 뒤 같은 키 재시도는 "작업대 없음"이 된다.

**호환·버전**

- **FR-025**: 버전 확인에 서버 버전, 프로토콜 버전 범위, 저장 형식 버전을 싣는다. 데스크톱은 지원하지 않는 서버에 붙지 않고 이유를 보여 준다. 서버는 모르는 저장 형식의 데이터 디렉터리를 열지 않는다(037 이후 규칙 유지).
- **FR-026**: 데스크톱이 띄울 서버 실행 파일은 정해진 규칙으로 찾는다: 명시적 설정 경로 → 앱 실행 파일 옆 → 개발 빌드 산출물 위치. 설치본 포함·서명(f)은 다음 증분이다.

### Key Entities

- **서버 인스턴스**: 한 데이터 디렉터리를 소유한 서버 프로세스 하나. 인스턴스 식별자, 세대, 버전, 상태(서빙·비우기·정지)를 가진다.
- **소유 잠금 / 시작 잠금**: 데이터 디렉터리별 단일 writer 보장(소유)과 시작 절차 직렬화(시작).
- **서버 안내 파일**: 소유 사용자만 읽는 원자적 파일. 끝점, 인스턴스 식별자, 세대, 버전, 사용자 소유 자격 증명(또는 위치).
- **소유자 주체**: 사용자 소유 자격 증명을 가진 클라이언트. 모든 작업대·run을 다루고 서버 정지를 요청한다.
- **창 주체**: 데스크톱 창 하나(043). 이제 서버가 등록·폐기를 관리한다.
- **클라이언트 임대**: 붙은 클라이언트가 만료 시간과 함께 잡는 서버 유지 요청.
- **활성 작업**: 유휴 종료를 막는 일(진행·예약 run, 권한 대기, orchestration 작업, 판정 전 변경). orchestration 작업은 배정된 진행 중 task와, 비우기 전 대기 task 중 **배정할 쪽이 있는 것**(살아 있는 coordinator가 turn 중이거나 그에게 전달할 알림이 남음)이다. 배정할 쪽이 없는 대기 task와 비우기가 시작된 뒤 만들어진 대기 task는 멈춤을 막지 않고 보류로 보고되며, 저장돼 있어 재시작 뒤 복구·재배정할 수 있다(구현 중 정책 변경, research R7). coordinator에게 전달할 알림은 전달 중이거나 대기 중이면 활동 작업이다. 재시도를 기다리는 실패 알림은 정해진 **실제 전달 실패 횟수**까지만 활동으로 세고, 그 뒤에는 멈춤을 막지 않고 "멈춘 알림"으로 보고한다. coordinator가 바빠서 받지 않은 경우(바쁨 거절)는 실패로 세지 않고, 마지막이 바쁨 거절이면 횟수와 무관하게 활동이다. 이런 알림은 전달된 것으로 바뀌지 않고 재시도 가능한 실패로 저장된 채 남는다(OCR 구현 리뷰, research R7).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 데스크톱에서 시작한 run이 데스크톱 프로세스를 실제로 종료한 뒤에도 계속되고, 데스크톱 없이 소유자 자격 증명으로 그 run을 조회·출력 이어 받기·취소하는 것이 실제 실행으로 확인된다(개발·배포 출처 빌드 각각).
- **SC-002**: 같은 데이터 디렉터리로 서버 시작을 동시에 10번 시도해도 데이터를 여는 서버는 정확히 하나이고, 나머지 시도는 모두 그 서버에 붙거나 "이미 있음"으로 끝난다.
- **SC-003**: 서버를 강제로 죽인 뒤 다음 시작이 남은 잠금·안내 파일을 복구하고 5초 안에 준비된다.
- **SC-004**: 서버 안내 파일과 자격 증명은 소유 사용자 외에는 읽을 수 없다(권한 검사).
- **SC-005**: 서버가 없는 상태에서 앱을 열면 서버가 한 번만 뜨고 창이 연결된다. 떠 있는 상태에서 열면 새로 띄우지 않는다.
- **SC-006**: 창을 닫은 뒤 그 창의 토큰으로 하는 호출·구독은 100% 거절되고, 그 창의 작업대의 run은 취소된다. 앱 전체 종료 뒤에는 작업대·run이 하나도 닫히지 않는다.
- **SC-007**: 임대·활성 작업이 없으면 정해진 유휴 시간 뒤 서버가 멈추고, 활성 run이 있으면 멈추지 않는다. 정지 요청 세 방식이 각각 정해진 결과를 낸다.
- **SC-008**: 비우는 중의 변경 호출은 100% "비우는 중"으로 거절되고 적용되지 않는다.
- **SC-009**: 작업대 닫기와 그 작업대 변경 호출의 완료 순서를 뒤집은 시험에서, 닫은 뒤 같은 키 재시도가 100% "작업대 없음"이다(#207).
- **SC-010**: 043의 화면 시험·통합 시험·앱 스모크(출력 + 강제 재연결, 새로고침 1회 전달)가 외부 서버 모드에서 기대값 변경 없이 통과한다.

## Assumptions

- 외부 서버가 기본 모드다. embedded 모드는 개발·시험용 명시 설정이며 8단계에서 호환 경로와 함께 지운다.
- 창 닫기 의미는 오늘과 같다(작업대 닫기 = 그 작업대의 run 취소, ADR 0005). 바뀌는 것은 "앱 전체 종료"다: 더 이상 작업대를 닫지 않는다.
- 앱을 다시 열었을 때 남은 작업대에 다시 붙는 화면은 이 증분 밖이다. 남은 작업대는 소유자 주체가 조회·닫기할 수 있다.
- 서버 비정상 종료 때 진행 중 run은 복구를 약속하지 않는다(설계 문서의 v1 보장). 다음 시작은 새 세대로 뜨고 판정 전 변경을 오늘 규칙으로 판정한다.
- 유휴 시간·임대 만료·시작 대기 시간은 계획에서 정한다(예: 유휴 수 분, 임대 수십 초 단위).
- 자식 프로세스 정리는 오늘 수준(run 취소 시 agent 프로세스 종료)을 유지하며, 강제 종료 뒤 잔여 자식 정리는 (d)로 남긴다.
- 설치본에 서버 실행 파일을 넣는 일(f)은 다음 증분이다. 이 증분의 배포 출처 확인은 디버그 번들 빌드와 옆에 둔 서버 실행 파일로 한다.
- 대상 플랫폼은 macOS(Apple Silicon)부터다. Windows·Linux의 잠금·권한 동작은 시험에서 가능한 범위만 확인하고 미검증 목록에 둔다.
