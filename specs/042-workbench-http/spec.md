**Status**: Draft

## 배경과 목적

037–041(1·2단계)로 서버 상태를 바꾸는 모든 경로가 하나의 계약(`Workbench.call`·`Workbench.events`)을 거치게 됐다. 지금은 그 계약을 **같은 프로세스 안에서만** 부를 수 있다. 데스크톱 화면은 Tauri 호환 어댑터로, MCP 도구는 in-process 호출로 부른다. HTTP/WebSocket 경로는 테스트 전용 harness에만 있다.

이 기능은 같은 계약을 **네트워크(로컬 루프백)로도** 부를 수 있게 한다. 운영 코드의 HTTP/WebSocket 어댑터를 데스크톱 앱 안의 **같은 서버 런타임**에 붙인다. 이것은 전체 목표(독립 서버 + 얇은 데스크톱)로 가는 3단계다. 다음 단계들은 이 어댑터를 그대로 쓴다. 4단계에서 화면이 이 경로로 옮기고, 5단계에서 같은 조립을 독립 서버 프로세스로 띄우며, 8단계에서 호환 어댑터를 지운다. 그래서 이번에 만드는 인증·연결 규칙은 임시가 아니라 이후 단계가 그대로 쓰는 규칙이어야 한다.

범위 밖: 화면의 호출 경로 전환(4단계), 독립 서버 프로세스·생명주기·자격 증명 파일(5단계), 원격 접속·TLS, CLI/TUI.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 인증된 로컬 클라이언트가 네트워크로 서버 계약을 부른다 (Priority: P1)

데스크톱 앱이 켜져 있는 동안, 인증 정보를 가진 로컬 클라이언트(4단계의 화면, 이후 CLI·독립 서버 클라이언트)는 루프백 주소로 연결한다. 먼저 호환성 협상(handshake)을 하고, 이어서 in-process와 **똑같은 결과·오류**로 조회와 변경을 부른다. 변경은 멱등성 키로 재시도해도 한 번만 적용된다. 이 경로는 데스크톱 화면이 지금 쓰는 경로와 **같은 서버 런타임**을 공유한다. 그래서 두 경로로 동시에 부른 변경도 저장소를 따로 쓰지 않는다.

**Why this priority**: 이후 모든 단계(화면 전환, 독립 서버, CLI)가 이 경로 위에 선다. 결과가 in-process와 조금이라도 다르면 4단계 전환에서 화면 동작이 바뀐다.

**Independent Test**: 앱 런타임(또는 같은 조립)을 루프백 임의 포트로 띄운다. 모든 계약 fixture를 in-memory 경로와 HTTP 경로로 실행해 결과·오류·이벤트가 같음을 확인하고, 두 경로를 섞어 부른 변경이 한 저장소에서 직렬화되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 유효한 자격 증명, **When** 지원하는 프로토콜 버전 목록으로 handshake하면, **Then** 서버가 하나를 골라 서버 버전·세대·계약 식별자와 함께 돌려주고, 이후 모든 응답이 그 버전을 싣는다.
2. **Given** 지원하지 않는 버전만 담은 handshake, **When** 보내면, **Then** 안정된 비호환 오류가 돌아오고 호출은 열리지 않는다.
3. **Given** 계약의 모든 operation, **When** 같은 입력을 in-process와 HTTP로 부르면, **Then** 결과·오류 코드·문구·오류 details가 같다.
4. **Given** 멱등성 키가 필요한 변경, **When** 같은 키로 두 번 보내면, **Then** 한 번만 적용되고 두 번째는 저장된 결과를 돌려준다. 키가 없으면 오늘과 같은 오류가 난다.
5. **Given** 데스크톱 화면이 Tauri 경로로 프로젝트를 만드는 동안, **When** HTTP 클라이언트가 같은 목록을 조회하면, **Then** 같은 저장 상태가 보인다(저장 주체는 하나다).

### User Story 2 - 이벤트를 네트워크로 구독하고 끊겼다 이어도 빠짐이 없다 (Priority: P2)

인증된 클라이언트는 먼저 짧게 유효한 1회용 구독 표를 받는다. 그 표로 WebSocket에 연결해 run·작업 영역·작업대 스트림을 구독한다. 연결 직후에는 지정한 위치 이후의 기록을 먼저 받고, 이어서 새 이벤트를 받는다. 이 사이에 빠지거나 겹치는 이벤트가 없다. 연결이 끊기면 새 표와 마지막 위치로 다시 이어 받는다. 장기 자격 증명은 URL에 남지 않는다.

**Why this priority**: 화면(4단계)이 run 출력·orchestration 갱신을 받는 경로다. 표가 재사용되거나 URL에 장기 토큰이 남으면 보안 경계가 무너진다.

**Independent Test**: 이벤트 계약 fixture를 in-memory와 WebSocket 두 경로로 실행해 같은 이벤트·gap을 받는지 확인한다. 표의 1회성·만료·권한 범위, 재연결 뒤 빠짐 없음도 확인한다.

**Acceptance Scenarios**:

1. **Given** 인증된 요청으로 받은 구독 표, **When** 제한 시간 안에 한 번 연결하면, **Then** 연결되고, 같은 표로 다시 연결하면 거절된다.
2. **Given** 만료된 표 또는 다른 주체의 표, **When** 연결하면, **Then** 거절되고 아무 이벤트도 흐르지 않는다.
3. **Given** 발행이 이어지는 run 스트림, **When** 위치 N에서 구독하면, **Then** N+1부터 빠짐·중복 없이 기록과 새 이벤트를 받는다(기록과 실시간 사이 경계 포함).
4. **Given** 연결이 끊긴 클라이언트, **When** 새 표와 마지막 위치로 다시 연결하면, **Then** 그 뒤 이벤트를 이어 받는다. 보관 한도로 사라진 구간은 오늘과 같은 gap으로 알린다.
5. **Given** 구독 권한이 없는 스트림(다른 작업대·다른 주체), **When** 표를 요청하거나 연결하면, **Then** 오늘 in-process 구독과 같은 거절 결과가 된다.

### User Story 3 - 로컬 서버가 원격 웹페이지·다른 주체로부터 보호된다 (Priority: P3)

사용자의 브라우저에서 열린 임의 웹사이트, DNS rebinding, 같은 머신의 다른 포트 서비스가 이 서버를 부를 수 없어야 한다. 서버는 루프백 주소에만 연결을 받는다. 요청의 Host와 Origin을 허용 목록과 **정확히** 대조하고, 인증 없는 요청을 거절한다. 브라우저에는 허용한 출처에만 필요한 만큼의 교차 출처 응답을 연다. 같은 규칙이 기존 AW MCP 서버에도 적용된다. 오늘 MCP 서버는 Origin을 접두사로 비교해 `http://127.0.0.1.evil.example` 같은 출처를 통과시킨다.

**Why this priority**: 로컬 HTTP 서버를 여는 순간 생기는 위험이다. 기능 경로(US1·US2)와 같은 PR에서 막아야 한다.

**Independent Test**: 허용되지 않은 Host/Origin, 접두사만 같은 출처, `null` Origin, 자격 증명 없음·잘못됨·만료, 크기 초과 요청을 보내 모두 거절되고 서버 상태가 바뀌지 않음을 확인한다. 같은 출처 검사를 MCP 서버에도 적용한다.

**Acceptance Scenarios**:

1. **Given** 루프백이 아닌 주소, **When** 연결을 시도하면, **Then** 서버가 그 주소에서 받지 않는다.
2. **Given** 허용 목록에 없는 Host 또는 Origin(접두사만 같은 출처·`null` 포함), **When** 호출·표 발급·WebSocket 연결을 하면, **Then** 거절되고 상태가 바뀌지 않는다.
3. **Given** 허용된 브라우저 출처의 사전 확인 요청, **When** 보내면, **Then** 필요한 메서드·헤더만 허용하고 쿠키 기반 자격 증명은 허용하지 않는다.
4. **Given** 자격 증명이 없거나 잘못되었거나 만료된 요청, **When** 보내면, **Then** 인증 오류가 돌아오고 오류 본문이 서버 내부 정보를 드러내지 않는다.
5. **Given** 허용 크기를 넘는 요청 본문, **When** 보내면, **Then** 거절되고 처리되지 않는다.
6. **Given** AW MCP 서버, **When** 접두사만 같은 출처로 요청하면, **Then** 거절된다(오늘은 통과한다).

### User Story 4 - 데스크톱과 agent가 짧은 자격 증명으로 연결된다 (Priority: P4)

데스크톱 앱은 서버와 같은 프로세스에서 자격 증명을 만든다. 화면(WebView)에는 넓은 비밀이 아니라 **출처·클라이언트에 묶인 짧게 유효한 데스크톱 토큰**만 건넨다. 이번 단계에서 화면은 아직 이 토큰으로 호출하지 않지만(4단계), 토큰을 받아 연결할 수 있어야 한다. agent는 오늘 받는 MCP 실행 토큰(run에 묶임)으로 같은 서버에 agent 주체로 연결할 수 있다. 권한은 in-process의 agent 주체와 같다.

**Why this priority**: 4단계 화면 전환과 5단계 독립 서버의 자격 증명 흐름이 이 규칙을 그대로 쓴다. 이번에는 화면이 쓰지 않으므로 US1–US3보다 뒤다.

**Independent Test**: 데스크톱 토큰을 발급받아 handshake·조회에 쓰고, 만료·다른 출처에서 쓰면 거절되는지 확인한다. MCP 실행 토큰으로 agent 주체 operation을 부르면 in-process와 같은 권한 결과가 나오는지, 폐기된 토큰은 거절되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 데스크톱 앱, **When** 화면이 연결 정보를 요청하면, **Then** 서버 주소와 짧게 유효한 데스크톱 토큰을 받는다(넓은 비밀 없음, 캐시 금지).
2. **Given** 만료된 데스크톱 토큰, **When** 호출하면, **Then** 인증 오류가 나고 다시 발급받으면 이어서 쓸 수 있다.
3. **Given** MCP 실행 토큰, **When** agent 주체 operation을 HTTP로 부르면, **Then** in-process agent 호출과 같은 결과·거절이 나고, 그 토큰의 run이 아닌 run으로는 부를 수 없다.
4. **Given** 폐기된 MCP 토큰(재시도·교대·작업대 닫기), **When** HTTP로 부르면, **Then** 거절된다.

### User Story 5 - 상태 확인과 계약 문서를 네트워크로 얻는다 (Priority: P5)

클라이언트와 운영자는 인증 없이 "살아 있음"을 확인한다. 이 응답은 버전·경로·프로젝트 정보를 드러내지 않는다. 인증한 뒤에는 "요청을 받을 준비가 됨"과 계약 문서(생성 타입의 원본)를 받는다. 계약 문서는 저장소에 커밋된 계약 파일과 같아야 한다.

**Why this priority**: 5단계 생명주기(준비 확인)와 클라이언트 생성의 기반이지만 이번 단계의 사용자 가치는 작다.

**Independent Test**: 인증 없이 살아 있음 확인은 성공하고 준비·계약 문서는 거절된다. 인증 뒤에는 준비 상태와 커밋된 계약과 같은 문서를 받는다.

**Acceptance Scenarios**:

1. **Given** 인증 없는 요청, **When** 살아 있음을 확인하면, **Then** 성공하고 본문에 버전·경로·프로젝트 정보가 없다.
2. **Given** 인증 없는 요청, **When** 준비 상태나 계약 문서를 요청하면, **Then** 인증 오류가 난다.
3. **Given** 인증된 요청, **When** 계약 문서를 받으면, **Then** 커밋된 계약 파일과 내용이 같다.

---

### Edge Cases

- 서버가 기동 복구(미완료 변경 판정)를 끝내기 전에 온 호출: 준비 상태가 아니면 호출을 열지 않는다(오늘 런타임은 조립이 끝난 뒤에만 쓰이므로, 어댑터도 조립 완료 뒤에 연결을 받는다).
- 포트 선택 실패(모든 시도 실패): 데스크톱 앱은 HTTP 경로 없이 계속 동작하고, 실패를 기록한다(화면은 아직 Tauri 경로를 쓰므로 기능 손실 없음).
- 앱 종료: 진행 중 HTTP 요청·WebSocket 연결을 닫고, 구독은 in-process 구독 해제와 같이 정리된다.
- 한 주체가 WebSocket을 너무 많이 열거나 느리게 읽는 경우: 오늘 이벤트 허브의 구독 상한·지연 구독자 gap 규칙을 그대로 따른다.
- 같은 멱등성 키를 in-process와 HTTP로 번갈아 보내는 경우: 같은 멱등 기록을 공유하므로 한 번만 적용된다.
- 구독 표를 발급받은 뒤 그 스트림 권한이 사라진 경우(작업대 닫힘 등): 연결 시점에 권한을 다시 확인하고, 이미 닫힌 스트림은 오늘처럼 gap(evicted)으로 알린다.
- 자격 증명·구독 표가 로그·추적 기록에 남는 경우: 남지 않아야 한다(요청 id·operation·주체 종류·지연만 기록).
- 오류 응답 형식: in-process 오류와 같은 코드·문구·details를 싣되, HTTP 상태 코드는 오류 코드에서 정해진다(오늘 테스트 경로와 같은 규칙).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 서버 계약 호출·이벤트 구독을 로컬 루프백 네트워크로 제공하는 어댑터를 운영 코드로 가져야 하며, 데스크톱 앱은 기동할 때 이 어댑터를 **자기 서버 런타임과 같은 인스턴스**에 붙여 연결을 받아야 한다(저장 주체 하나).
- **FR-002**: 계약 테스트는 테스트 전용 경로가 아니라 이 운영 어댑터를 임의 루프백 포트로 띄워 실행해야 하며, 모든 계약 fixture·이벤트 fixture가 in-process와 네트워크 경로에서 같은 결과·오류·이벤트를 내야 한다.
- **FR-003**: 호환성 협상은 클라이언트가 지원하는 프로토콜 버전 목록을 받아 하나를 고르거나 안정된 비호환 오류를 내야 하며, 서버 버전·세대·계약 식별자·저장 형식 버전을 돌려줘야 한다. 고른 버전은 이후 응답과 WebSocket 첫 프레임에서 확인할 수 있어야 한다.
- **FR-004**: 계약의 모든 operation(조회·변경)을 네트워크로 부를 수 있어야 하며, 변경의 멱등성 규칙(영속·세대 범위)은 in-process와 같은 기록을 공유해야 한다. 변경 operation은 중단·재시작 판정 증거(서버 재시작 뒤 같은 키 재시도가 다시 적용되지 않음 포함)가 있을 때만 연다.
- **FR-005**: 이벤트 구독은 인증된 요청으로 발급한 **짧게 유효한 1회용 구독 표**로만 연결해야 한다. 표에는 발급 주체·허용 스트림·출처·만료가 묶여야 하고, 연결 직전에 원자적으로 소모되어야 한다. 장기 자격 증명은 URL에 싣지 않는다.
- **FR-006**: WebSocket 구독은 지정 위치 이후의 기록과 실시간 이벤트를 빠짐·중복 없이 이어 보내야 하며(오늘 이벤트 허브의 원자적 구독 경계), gap·세대 규칙은 in-process 구독과 같아야 한다.
- **FR-007**: 서버는 루프백 주소에만 연결을 받아야 하며, 요청의 Host와 Origin을 허용 목록과 **정확히** 대조해야 한다(접두사·접미사 비교 금지, `null` Origin 거절). Origin이 없는 비브라우저 클라이언트는 자격 증명으로만 판단한다. Origin은 인증 수단이 아니다.
- **FR-008**: 브라우저 교차 출처 응답은 허용한 출처·메서드·헤더에만 열어야 하며, 쿠키 기반 자격 증명은 허용하지 않는다. WebSocket 연결은 교차 출처 설정과 별개로 Host·Origin·구독 표를 모두 검사해야 한다.
- **FR-009**: 살아 있음 확인을 뺀 모든 경로는 인증을 요구해야 한다. 자격 증명은 (a) 데스크톱 앱이 발급한 짧게 유효한 데스크톱 토큰, (b) 오늘의 MCP 실행 토큰(run에 묶인 agent 주체), (c) 계약 테스트용 테스트 주체다. 각 자격 증명의 권한은 in-process의 같은 주체와 같아야 한다.
- **FR-010**: 데스크톱 앱은 화면에 서버 주소와 짧게 유효한 데스크톱 토큰을 건네는 연결 정보 경로를 제공해야 한다(넓은 비밀 없음, 캐시 금지, 만료 전 재발급). 이번 단계에서 화면의 호출 경로는 바꾸지 않는다.
- **FR-011**: 폐기된 MCP 실행 토큰은 네트워크 경로에서도 즉시 거절되어야 한다.
- **FR-012**: 요청 본문 크기에 상한을 두고 초과 요청을 처리하지 않아야 한다.
- **FR-013**: 인증 없는 살아 있음 확인은 버전·경로·프로젝트 정보를 드러내지 않아야 하며, 인증된 준비 상태 확인과 계약 문서 조회를 제공해야 한다. 계약 문서는 커밋된 계약 파일과 같아야 한다.
- **FR-014**: 자격 증명·구독 표·prompt 원문은 로그·추적 기록에 남지 않아야 한다. 요청 id·operation·주체 종류·지연만 남긴다.
- **FR-015**: AW MCP 서버의 출처 검사를 같은 정확 대조 규칙으로 바꿔야 한다(접두사만 같은 출처 거절).
- **FR-016**: 네트워크 어댑터를 시작하지 못해도 데스크톱 앱은 기존 경로로 계속 동작해야 하며 실패를 기록해야 한다.
- **FR-017**: 앱 종료 때 네트워크 어댑터는 연결을 닫고 구독을 in-process 구독 해제와 같이 정리해야 한다.
- **FR-018**: 화면 코드와 화면이 쓰는 Tauri 호환 경로의 동작은 바뀌지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **연결 끝점(Endpoint)**: 데스크톱 앱이 띄운 네트워크 어댑터의 루프백 주소·포트. 앱 수명 동안 유효하다.
- **데스크톱 토큰(Desktop Token)**: 데스크톱 앱이 화면에 건네는 짧게 유효한 자격 증명. 출처·클라이언트 인스턴스·주체에 묶인다. 메모리 전용이다.
- **구독 표(Event Ticket)**: 인증된 요청으로 발급하는 1회용·단기 WebSocket 연결 허가. 발급 주체·허용 스트림·cursor·출처·만료를 담는다.
- **handshake 결과**: 고른 프로토콜 버전, 서버 버전(CALVER), 세대, 계약 식별자, 저장 형식 버전, 서버 인스턴스 id.
- **허용 출처 목록(Origin Allowlist)**: 데스크톱 WebView의 개발·배포 출처를 정확한 값으로 나열한 목록.

## Constitution Alignment *(mandatory)*

- **Monorepo boundary**: 네트워크 어댑터(경로·인증·출처·구독 표·상태 확인·계약 문서)는 공유 core 쪽 크레이트에 둔다(이후 독립 서버·CLI가 같은 조립을 쓰므로 앱에 두지 않는다). 데스크톱 앱(`apps/agentic-workbench/src-tauri`)은 기동·자격 증명 발급·MCP 토큰 연결·연결 정보 전달만 한다. `packages/workbench-client`는 생성 타입 갱신만 한다. 화면 코드(`apps/agentic-workbench/src`), `crates/acp-agent-core`, `packages/agent-client`는 불변을 목표로 한다.
- **Frontend layering**: 변경 없음 목표. 연결 정보 경로는 추가만 하고 호출하지 않는다(4단계).
- **Backend boundary**: 어댑터는 계약(`Workbench` trait)만 부르는 inbound 어댑터다. 인증 판정은 포트(자격 증명 해석)로 추상화해, 데스크톱 토큰·MCP 토큰의 구체 저장은 조립 쪽이 주입한다.
- **Shared core vs UI**: 순수 core만 공유한다.
- **Persistence and safety**: 저장 주체는 하나(같은 런타임 인스턴스)다. 루프백 bind, 정확 Host/Origin, 인증, 단기 1회용 표, 본문 상한, 로그 비노출. 새 영속 저장은 없다(토큰·표는 메모리).
- **Documentation and Storybook**: `docs/workbench-seam.md`에 네트워크 어댑터 절(경로·인증·출처 규칙, Mermaid), 정본 진행 각주를 갱신한다. 되돌리기 어려운 결정(인증 모델·구독 표)은 ADR로 남긴다. Storybook N/A.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 모든 계약 fixture와 이벤트 fixture가 in-process 경로와 운영 네트워크 경로에서 같은 결과·오류·이벤트를 낸다(차이 0건).
- **SC-002**: 보안 거절 시나리오(허용 안 된 Host/Origin, 접두사만 같은 출처, `null` Origin, 자격 증명 없음·잘못됨·만료, 재사용·만료·다른 주체의 구독 표, 크기 초과, 폐기된 MCP 토큰) 전부가 거절되고, 그 뒤 서버 상태가 바뀌지 않는다.
- **SC-003**: WebSocket 구독에서 기록→실시간 경계에 이벤트를 주입하는 경합 시험 1,000회 이상에서 빠짐·중복이 0건이다.
- **SC-008**: 네트워크에 연 변경 operation 전부가 중단·재시작 판정 증거 시험을 가진다(증거 없는 변경 operation 0개).
- **SC-004**: in-process와 네트워크 경로를 섞어 같은 대상에 동시 변경을 100회 이상 보내도 잃어버린 변경이 0건이다(저장 주체 하나).
- **SC-005**: 데스크톱 앱을 실제로 띄워 네트워크 끝점에 연결하고(살아 있음 확인, 발급한 데스크톱 토큰으로 handshake·조회, 구독 표로 WebSocket 연결), 앱 재기동 뒤 다시 연결할 수 있다.
- **SC-006**: 화면 코드 diff가 0건이고, 기존 화면 동작·오류 문구가 이전과 같다.
- **SC-007**: 로그·추적 기록에 자격 증명·구독 표 문자열이 0건 나타난다(시험으로 확인).

## Assumptions

- 목표는 계약의 모든 operation을 네트워크로 여는 것이다. 다만 정본 문서의 조건("변경 경로는 중단·복구 시험을 통과한 operation만 연다")을 유지한다. **정상 경로 parity는 중단 안전성의 근거가 아니다.** 변경 operation마다 기존 중단·재시작 판정 증거를 확인하고, 없는 operation은 이번 기능에서 증거 시험을 추가한 뒤에 연다(목록과 보강 내용은 research R13). 네트워크가 새로 만드는 위험은 "응답을 잃은 클라이언트가 서버 재시작 뒤 같은 키로 재시도"하는 경우이며, 이 재시도가 다시 적용되지 않음을 증명해야 한다.
- 인증 모델은 2026-09-26 grill의 결정 8을 따른다: local-only, 127.0.0.1 bind, exact Host/Origin, CORS allowlist, HTTP bearer, 30초 1회용 WS ticket, 짧은 desktop token, MCP `origin_allowed` 결함 수정.
- 데스크톱 토큰 발급은 서버와 같은 프로세스 안에서 한다. OS credential store·자격 증명 파일·descriptor는 5단계(독립 서버)의 몫이다.
- 외부 도구(CLI 등)가 이번 단계에서 쓸 공개 자격 증명 경로는 두지 않는다. 앱 실제 연결 스모크는 앱이 발급한 토큰을 쓰는 방법(개발 빌드 전용 진단 경로 등)으로 한다. 방법은 plan에서 정한다.
- 허용 출처 목록은 실제 WebView 요청의 Origin을 캡처해 고정한다(개발 `http://localhost:1420`, macOS 배포 `tauri://localhost` 등). 추정 wildcard는 쓰지 않는다.
- 프로토콜 버전은 현재 1개이며, handshake의 협상 규칙은 여러 버전을 받을 수 있게 둔다.
- 기존 MCP 서버(교환·제목·orchestration 도구)는 자기 포트와 경로를 유지한다. 이번에는 출처 검사만 고친다. MCP 서버를 네트워크 어댑터로 합치는 일은 범위 밖이다.
