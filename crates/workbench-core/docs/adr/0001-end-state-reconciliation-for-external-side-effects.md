# 외부 부작용 변경의 재시작 판정은 종료 상태 규칙을 따른다

변경 기록(operation ledger)은 재시작 시 미확정 `대기` 기록을 자동 재실행 없이 `적용됨` 또는 `불명`으로 판정한다. `project.create`는 예약 id가 저장 파일에 있는지로 판정하는 **증거 규칙**을 쓰지만, Git worktree 생성·삭제(`git.createWorktree`·`git.deleteWorktree`)에는 예약 id가 없고 Git 내부에 marker를 심을 수도 없다. 그래서 외부 부작용 변경은 `대기` 기록에 서버가 기본값을 채운 최종 경로를 남기고, 재시작 시 생성은 그 경로가 `git worktree list`에 **있으면**, 삭제는 **없으면** `적용됨`, 그 외는 `불명`으로 판정한다(**종료 상태 규칙**). 원하는 종료 상태가 성립하면 누가 만들었는지는 결과에 영향이 없고, 항상 `불명`으로 두면 실제로 만들어진 worktree가 재시도에서 "already exists" 오류로만 드러나기 때문이다.

## Considered Options

- 항상 `불명` — 관측 로직이 없어 가장 보수적이지만, 성공한 생성도 불명으로 보여 사용자가 새 키로 재시도해야 한다.
- 037과 같은 증거 규칙 강제(branch 이름·marker) — 사용자가 직접 준 branch 이름에는 붙일 수 없고 Git 내부를 바꿀 수 없어 반쪽만 동작한다.

## Consequences

- 같은 ledger 안에 두 판정 규칙이 공존한다: 저장 파일 변경은 증거 규칙, 외부 부작용 변경은 종료 상태 규칙. 새 외부 부작용 operation을 추가할 때는 종료 상태를 관찰하는 방법을 함께 정의해야 한다.
- 사용자가 같은 경로에 수동으로 worktree를 만든 경우에도 `적용됨`으로 판정된다. 결과 상태가 같으므로 무해하다.
